# ۳۸. تحویل واقعی پرونده: «دادن» یعنی جابه‌جا شدن نمونه

تاریخ: ۲۰۲۶-۱۱-۱۲ — جلسه‌ی سی‌وچهارم

## ۱. مسئله

در جلسه‌ی ۳۱ پرونده به سیستم آیتم وصل شد، ولی **تحویل** هنوز فقط حرف بود.
گره‌های تحویل در `farhadi_archive.txt` و `reza_office.txt` این خط‌ها را داشتند:

```text
[do] flag.file.taken = false
[do] flag.quest.file = 3
[do] flag.delivery = archive
```

یعنی داستان می‌نوشت «پرونده تحویل داده شد»، اما `ItemInstance` هنوز در ظرف
`player` بود. نتیجه‌ی دیدنی:

| بعد از تحویل | انتظار داستان | واقعیت |
| --- | --- | --- |
| کارت پرونده در «وسایل» | نباشد | **باز هم بود** |
| `F10` → `item.file.sealed` | `0` | `1` |
| ورود دوباره به صحنه | پرونده روی میز نباشد | `SceneItemBinding` نسخه‌ی مهرشده‌ی **تازه** می‌ساخت |

و بدتر: شرط ورود به گره تحویل هم `flag.file.taken` بود. اگر بازیکن پرونده را
روی زمین می‌انداخت، پرچم `false` می‌شد و گره تحویل دیگر باز نمی‌شد — در حالی که
پرونده در دنیا وجود داشت.

## ۲. اصلاح یک: گرامر تحویل

اثر تازه:

```text
[do] item.give.<شناسه‌ی آیتم> = <شناسه‌ی ظرف>
[do] item.give.file.sealed = archive
[do] item.give.file.sealed = reza
```

| مرحله | چه می‌شود |
| --- | --- |
| `DialogueRunner.ApplyEffect` | اول قلاب `ExternalEffect` را صدا می‌زند |
| `ItemDialogueEffect.Handle` | اگر متن با `item.give.` شروع شود، آیتم و ظرف را جدا می‌کند |
| `InventoryManager.Ensure(container, "item.container.<id>")` | ظرف مقصد اگر نبود ساخته می‌شود |
| `InventoryManager.Give(id, container)` | همه‌ی پشته‌های آن تعریف را با `Move` جابه‌جا می‌کند |
| نتیجه | **همان نمونه** با `state.sealed` و `state.read` در مقصد می‌نشیند |

چرا قلاب و نه `using TehranNoir.Items` در `DialogueRunner`؟ چون جهت وابستگی
باید یکی بماند: آیتم‌ها به دیالوگ وابسته‌اند، نه برعکس. موتور دیالوگ نمی‌داند
آیتم چیست؛ فقط اگر کسی گوش بدهد، اثر را به او می‌دهد.

`Give` عمداً فقط وقتی جواب می‌دهد که آیتم همراه بازیکن باشد؛ اگر چیزی همراه
نباشد `NotFound` می‌دهد و **نسخه‌ی تازه نمی‌سازد**.

همین یک خط در `PlaceInteractable` هم کار می‌کند، چون آن هم اثرهای Inspector را
از `DialogueRunner.ApplyEffect` رد می‌کند:

```text
item.give.file.sealed = reza
flag.delivery = desk
flag.quest.file = 2
```

## ۳. اصلاح دو: شرط از خود آیتم

| جا | قبل | بعد |
| --- | --- | --- |
| `farhadi_archive.txt` (ورود به تحویل) | `flag.file.taken == true` | `item.file.sealed >= 1` |
| `reza_office.txt` (`carrying`) | `flag.file.taken == true` | `item.file.sealed >= 1` |
| `case_file.txt` (قدم `deliver`) | `flag.file.taken == true` | `item.file.sealed >= 1` |
| `TalkInteractable` (کار «دادن») | فقط نام متغیر | **هر شرطی** با گرامر `[if]`: `item.file.sealed >= 1` |

`item.file.sealed` همان پروجکشن است که `InventoryManager.SyncProjection` از
تعداد همراه می‌سازد؛ پس همیشه با واقعیت یکی است. `flag.file.taken` می‌ماند،
ولی دیگر **مرجع** نیست؛ فقط یک کپی داستانی است.

`TalkInteractable` حالا شرط را یک بار با `ConditionParser` می‌خواند و کش می‌کند؛
خطای تایپی هم یک بار در Console گزارش می‌شود، نه هر فریم.

## ۴. اصلاح سه: آبجکت صحنه نسخه‌ی مرده نمی‌سازد

`SceneItemBinding.Ensure` قبلاً فقط در ظرف `world` دنبال نمونه می‌گشت. اگر پرونده
در جیب یا بایگانی بود، نمونه‌ای در `world` نبود و یک **نسخه‌ی تازه** ساخته می‌شد.

| ابزار تازه | کار |
| --- | --- |
| `SceneItemBinding.FindExisting(id)` | اول زمین، بعد همه‌ی ظرف‌ها؛ نمونه‌ی آزاد همان تعریف را برمی‌گرداند |
| `PickupInteractable.Awake` | اگر نمونه مال زمین نیست → `_taken = true` و مخفی |

نتیجه: با لود شدن دوباره‌ی صحنه، پرونده‌ای که در بایگانی است روی میز ظاهر نمی‌شود
و تعداد کل نمونه‌ها همیشه یک می‌ماند.

## ۵. تست‌ها و گیت

`ItemSelfTest`: **۶۰ بررسی** (۵۳ قبلی + گروه `TestHandover`).

| تست تازه | چه چیزی را تضمین می‌کند |
| --- | --- |
| تحویل: پرونده از جیب بیرون رفت | `CountOf("file.sealed") == 0` |
| تحویل: در بایگانی نشست | ظرف `archive` یک نمونه دارد |
| تحویل: همان نمونه است | `InstanceId` عوض نشده |
| تحویل: مهرِ شکسته همراه نمونه رفت | `state.sealed == "0"` در مقصد |
| تحویل: پروجکشن صفر شد | `item.file.sealed == 0` |
| تحویل دوباره نسخه نمی‌سازد | `Give` دوم `NotFound` و تعداد کل ۱ |
| آبجکت صحنه به نمونه‌ی بایگانی وصل می‌شود | `FindExisting` همان نمونه را می‌دهد |

تست از راه واقعی `DialogueRunner.ApplyEffect("item.give.file.sealed = archive")`
می‌رود، نه با صدا زدن مستقیم `InventoryManager`.

### گیت پنجم: `tools/storycheck.py`

شناسه‌ی آیتم در داده‌ی داستان هیچ خطای کامپایلی نمی‌دهد؛ `item.file.seal`
همیشه نادرست است و دیالوگ بی‌صدا مسیر دیگری می‌رود. این ابزار بررسی می‌کند:

| بررسی | خطا |
| --- | --- |
| `item.<id>` در `[if]` / `[when]` / `[start]` / `[done]` | آیتم ناشناس |
| `[do] item.give.<id> = <ظرف>` | آیتم ناشناس یا ظرف خالی |
| `[do] item.<id> = ...` | نوشتن دستی پروجکشن |

خروجی سالم: `story files: 9 refs: 6 items: 6 problems: 0`.
تخریب (چهار خط بد): `problems: 4` و کد خروج ۱.

### باگی که وسط این کار پیدا شد

`cscheck.py`، `symcheck.py` و `argcheck.py` هیچ‌وقت `sys.exit` صدا نمی‌زدند؛
پس `preflight.sh` با `|| status=1` هیچ‌وقت خطا را نمی‌دید و **همیشه سبز** بود.
حالا هر سه با کد خروج غیرصفر برمی‌گردند و با یک فایل خرابِ آزمایشی ثابت شد که
`preflight_exit=1` می‌شود.

همچنین `symcheck` فیلدهای `Func<...>` را «فراخوانی ناشناس» می‌دید؛ حالا
`DECL_DELEGATE` آن‌ها را به‌عنوان چیزِ قابل صدا زدن می‌شناسد. با حذف همان فیلد
ثابت شد که باز هم خطا را می‌گیرد.

## ۶. تنظیم دستی، محدودیت‌ها و قدم بعد

| # | کجا | مقدار |
| --- | --- | --- |
| ۱ | `Reza` → `TalkInteractable` | `Handover Variable = item.file.sealed >= 1` |
| ۲ | `DeskPoint` → `PlaceInteractable` | `item.give.file.sealed = reza`، `flag.delivery = desk`، `flag.quest.file = 2` |
| ۳ | خانم فرهادی | `DialogueStarter` با `Dialogue/farhadi_archive` و همان شرط تحویل |

| مورد | وضعیت |
| --- | --- |
| تحویل چندپشته‌ای نیمه‌کاره | اگر وسط `Give` ظرف مقصد پر شود، پشته‌های قبلی جابه‌جا شده‌اند؛ برای ظرف بی‌سقف پیش نمی‌آید |
| تحویل به یکی از ظرف‌های همراه (`player` / `pockets` / `equipped`) | معنی ندارد؛ `Move` رد می‌کند |
| تحویل به `world` | `storycheck` رد می‌کند؛ برای برگرداندن به زمین از «انداختن» استفاده کن |
| ظرف بایگانی در فایل ذخیره | ذخیره می‌شود (هر ظرف با شناسه)، ولی منوی توقف هنوز محتوای ظرف‌های غیر از جیب را نشان نمی‌دهد |

**قدم بعد:** نشان دادن ظرف‌های دیگر (بایگانی، میز رضا) در تب «وسایل» یا یک تب
«محیط»، تا بازیکن ببیند پرونده کجا رفت؛ بعد از آن، ذخیره/بارگذاری منوی توقف.
