# ۵۰ — مدل سه‌بعدی از Poly Haven

## ۱. جواب کوتاه

**من نمی‌توانم دانلود کنم.** این جعبه فقط به چند دامنه دسترسی دارد
(`github.com`، npm، pypi) و `polyhaven.com`، `cdn.polyhaven.com` و
`dl.polyhaven.org` همه بسته‌اند:

```text
curl: (35) OpenSSL SSL_connect ... in connection to polyhaven.com:443
```

**ولی سایت را می‌بینم.** صفحه‌ها را خوانده‌ام و اسم و اندازه و فرمت دارایی‌ها
را از API گرفته‌ام. پس کاری که کرده‌ام این است: مسیر گذاشتن مدل را آماده
کرده‌ام، و مدل را خودت می‌گذاری. سه دقیقه کار تو، یک کلیک.

## ۲. مجوز

Poly Haven همه‌ی مدل‌ها، بافت‌ها و HDRIها را **CC0** منتشر می‌کند: مالکیت
عمومی، بدون شرط، برای پروژه‌ی تجاری هم. پس این‌جا هیچ نگرانی مجوز نیست.

## ۳. فرمت درست برای ما

هر مدل چهار فرمت دارد (از API):

```text
blend   gltf   usd   fbx
```

یونیتی `fbx` را **بدون هیچ پکیجی** می‌خواند. پس همیشه:

```text
FBX → 2k  (یا 1k برای وسایل کوچک)
```

نسخه‌ی `4k` هم هست، ولی ۴۰۹۶ پیکسل برای یک سینی سیگار در دوربین بالاسری
اسراف است و حجم صحنه را سه برابر می‌کند.

مقایسه‌ی حجم، برای یک صندلی:

| کیفیت | حجم بافت‌ها | مناسب |
| --- | --- | --- |
| 4k | ۲۸ مگابایت | رندر، نه بازی |
| 2k | ۷ مگابایت | پیش‌فرض |
| 1k | ۱.۸ مگابایت | وسایل کوچک: سینی، لیوان، چراغ |

هر fbx حدود ۲۵۰ کیلوبایت است و بافت‌ها در پوشه‌ی `textures/` کنارش می‌آیند.

## ۴. سه قدم

### قدم یک — دانلود

از دسته‌بندی‌های Poly Haven، این‌ها به این پروژه می‌خورند:

```text
https://polyhaven.com/models/furniture
https://polyhaven.com/models/lighting
https://polyhaven.com/models/office-stationery
```

چند دارایی که دیدم و به صحنه‌ها می‌خورند:

| دارایی | لینک | جای پیشنهادی |
| --- | --- | --- |
| Metal Office Desk | `polyhaven.com/a/metal_office_desk` | `Desk_814`، `Lobby_Desk` |
| Dining Table | `polyhaven.com/a/dining_table` | میز چای‌خانه |
| Vintage Day Bed | `polyhaven.com/a/vintage_day_bed` | `Bed_Frame` |
| Mid Century Lounge Chair | `polyhaven.com/a/mid_century_lounge_chair` | `Chair_814` |
| Wall Clock | `polyhaven.com/a/wall_clock` | دیوار لابی |
| Cigarette Pack | `polyhaven.com/a/cigarette_pack` | میز شب ۸۱۴ |
| Pocket Watch | `polyhaven.com/a/pocket_watch` | جیب سوکولوف |

و در دسته‌ی `lighting` دنبال `Chandelier 01` بگرد — لوستر برنجی با آباژور
پارچه‌ای، دقیقاً همان چیزی که لابی این دوره می‌خواهد.

### قدم دو — گذاشتن با نام درست

فایل را با **همان نامی** که در `model-slots.txt` آمده ذخیره کن:

```text
Assets/_Project/Art/Models/Slots/ashtray.fbx
Assets/_Project/Art/Models/Slots/ashtray/textures/Ashtray_diff_2k.jpg
```

فهرست کامل جای‌ها:

```text
Assets/_Project/Art/Models/model-slots.txt
```

هجده جای باز. هر کدام را پر نکنی، همان آبجکت جعبه‌ی ساده می‌ماند — و این
خطا نیست.

### قدم سه — دو منو در یونیتی

```text
Tehran Noir → مدل‌ها → درست‌کردن متریال‌ها (URP)
Tehran Noir → مدل‌ها → جایگزینی در همه‌ی صحنه‌ها
```

**ترتیب مهم است.** اول متریال، بعد گذاشتن.

## ۵. چرا متریال لازم است

این پروژه URP است. یونیتی وقتی `fbx` را ایمپورت می‌کند، متریال‌ها را با
شیدر **Standard** می‌سازد — که در URP کار نمی‌کند و همه‌چیز **صورتی** می‌شود.
این نه باگ یونیتی است نه باگ ما؛ فقط دو رندر پایپ‌لاین جدا.

`ModelSwapper` این را حل می‌کند: بافت‌های کنار فایل را با قاعده‌ی نام
پیدا می‌کند، یک متریال `Universal Render Pipeline/Lit` می‌سازد و روی مدل
می‌گذارد.

```text
<نام>_diff_2k.jpg     → Base Map
<نام>_nor_gl_2k.jpg   → Normal Map
<نام>_rough_2k.jpg    → زبری
```

## ۶. چرا اندازه از فایل گرفته نمی‌شود

بعضی مدل‌ها در متر می‌آیند، بعضی در سانتی‌متر، بعضی صد برابر بزرگ. اگر
اندازه را از فایل بگیری، یک صندلی می‌تواند کل اتاق را بپوشاند.

پس ابزار اندازه‌ی مدل را با **جعبه‌ای** که آن آبجکت از قبل اشغال کرده تطبیق
می‌دهد، و یکنواخت بزرگ می‌کند تا مدل کشیده نشود. نتیجه: چیدمان صحنه دقیقاً
همان می‌ماند، فقط جای جعبه‌ها مدل واقعی است.

سه تغییردهنده، وقتی لازم شد:

```text
Chair_814 = Slots/chair.fbx | rotY=90
Ashtray_814_Case = Slots/ashtray.fbx | stretch=1
Chandelier_1 = Slots/chandelier.fbx | lift=-0.2
```

| تغییردهنده | کار |
| --- | --- |
| `rotY=90` | اگر مدل رو به دیوار بود |
| `stretch=1` | کشیدن در سه محور؛ برای چیزهای تخت مثل فرش و کاغذ |
| `lift=0.05` | بالا بردن؛ برای لوستر و چراغ سقفی |

## ۷. کولایدر

مدل تازه کولایدر **نمی‌آورد**: جعبه‌ی قبلی کولایدر خودش را دارد و همان
سرِ جایش می‌ماند. فقط رندررش خاموش می‌شود. پس تعامل با در، سینی، پیشخوان و
هر چیز دیگری دقیقاً مثل قبل کار می‌کند.

اگر مدل کولایدر داشت، ابزار برش می‌دارد تا دو کولایدر روی هم نیفتد.

## ۸. ابزار بررسی

```text
python3 tools/modelcheck.py
```

گام دوازدهم `preflight`. سه چیز را می‌گوید:

- کدام خط فهرست بدشکل است؛
- کدام نام آبجکت در هیچ صحنه‌ای نیست (تایپو)؛
- چند جای دیگر خالی است.

الان:

```text
جای مدل: ۰ پُر، ۱۸ خالی از ۱۸
problems: 0
```

هر بار که یکی را بگذاری، این عدد بالا می‌رود. یک نشانگر پیشرفت است، نه خطا.

## ۹. دو محدودیت

- **دانلود با توست.** من فقط GitHub و npm و pypi را می‌بینم.
- **در Unity بازی نشده.** ابزار نوشته و بررسی شده، ولی اولین `Play` با مدل
  واقعی مال توست. اگر مدلی بد نشست، `rotY` و `lift` را عوض کن؛ فایل صحنه
  را دستی نمی‌خواهد.
