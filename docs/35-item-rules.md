# ۳۵. آیتم‌ها با قاعده، نه با کامپوننت

تاریخ: ۲۰۲۶-۱۱-۱۲ — جلسه‌ی بیست‌وپنجم

## ۱. تصمیم

نسخه‌ی اول (سند ۳۴) برای هر دسته یک کامپوننت جدا داشت:
`DocumentComponent`، `WeaponComponent`، `KeyComponent` و…

**این تصمیم برگشت.** دلیل، خواسته‌ی صریح تو:

> «نمی‌خوام برای هر آیتم بیام کامپوننت ایجاد کنم… هر چقدر خواستم فلگ بدم
> که تو چه شرایطی باید و چه شرایطی ایجاد می‌کنه.»

پس رفتار آیتم **داده** است، نه کلاس. هر آیتم هر تعداد قاعده می‌خواهد:

```
قاعده = فعل + شرط + اثر
```

| بخش | یعنی | مثال |
| --- | --- | --- |
| فعل | چه کاری | `read`، `open`، `unlock`، `use` |
| شرط | کِی مجاز است | `state.sealed = 0` |
| اثر | چه چیزی را عوض می‌کند | `state.read = 1; flag.letter.read = true` |

نتیجه: آیتم تازه = یک خط در `items.txt`. صفر خط C#.

## ۲. گرامر کامل

هر خط:

```
id | فارسی | انگلیسی | دسته | بیشترین تعداد | گزینه‌ها
```

گزینه‌ها با `|` جدا می‌شوند و هر کدام `key=value` است.

### ۲.۱ گزینه‌های ساده

| کلید | معنا |
| --- | --- |
| `weight=0.1` | وزن هر عدد |
| `value=2` | ارزش پایه |
| `flags=use,drop,trade,store,examine,destroy,equip` | اجازه‌های کلی |
| `icon=Icons/Keys/archive` | مسیر در `Resources` |
| `prefab=Prefabs/Items/key` | مدل سه‌بعدی |
| `sub=police` | زیردسته |
| `desc.fa=…` / `desc.en=…` | شرح |
| `doc=Documents/file_sealed` | سند خواندنی |

### ۲.۲ وضعیت اولیه

`state.<کلید>=<مقدار>` — هر تعداد که بخواهی. روی هر نمونه می‌نشیند، نه روی تعریف.

```
state.sealed=1 | state.read=0 | state.ammo=8 | state.owner=nader
```

### ۲.۳ قاعده‌ها

| کلید | معنا |
| --- | --- |
| `<فعل>.if=<شرط>` | شرط اجرا؛ خالی = همیشه |
| `<فعل>.do=<اثر>; <اثر>` | اثرها، با `;` |
| `<فعل>.consume=1` | یک عدد از آیتم کم شود |
| `<فعل>.target=door.archive` | فقط برای این هدف (کلید/قفل) |

برای قاعده‌ی دوم همان فعل، شماره اضافه کن: `open.if.2`، `open.do.2`.

**شرط** با همان گرامر `[if]` دیالوگ نوشته می‌شود (`=` و `==` هر دو برابرند)
و می‌تواند این‌ها را بخواند:

| چه چیزی | مثال |
| --- | --- |
| وضعیت همین آیتم | `state.sealed = 0` |
| تعداد آیتم‌ها در جیب | `item.ammo.9mm >= 1` |
| دنیای داستان | `flag.letter.opened = true`، `rel.reza > 10` |
| دانش افراد | `known.reza.secret = true` |

**اثر** با گرامر `[do]`:

| نوع | مثال | کجا می‌نشیند |
| --- | --- | --- |
| وضعیت آیتم | `state.read = 1` | روی همان نمونه |
| دنیا | `flag.door.archive = true` | `WorldState` |
| عدد دنیا | `rel.reza - 5`، `stat.energy + 5` | `WorldState` |

اثر روی «تعداد آیتم» (`item.x - 1`) نوشته نشود؛ شمارش را `InventoryManager`
نگه می‌دارد. برای کم‌کردن یک عدد از خود آیتم، `consume=1` بگذار.

### ۲.۴ فعل‌ها

`use`، `examine`، `equip`، `unequip`، `drop`، `read`، `open`، `close`،
`consume`، `unlock`، `give`، `store`، `reload`.

اگر برای فعلی قاعده ننوشته باشی، رفتار پیش‌فرض از پرچم‌ها می‌آید:

| فعل | پیش‌فرض |
| --- | --- |
| `examine` | اگر `flags` شامل `examine` |
| `drop` | اگر `flags` شامل `drop` |
| `equip` / `unequip` | اگر `flags` شامل `equip` |
| `read` | اگر `doc=` داشته باشد |
| `use` / `consume` | اگر `flags` شامل `use` |

## ۳. نمونه‌های واقعی (همان `items.txt`)

### پرونده‌ی مهرشده

```
file.sealed | پرونده‌ی مهرشده | Sealed file | document | 1
| weight=0.1 | sub=police | doc=Documents/file_sealed
| state.sealed=1 | state.read=0
| open.if=state.sealed = 1
| open.do=state.sealed = 0; flag.letter.opened = true
| read.if=state.sealed = 0
| read.do=state.read = 1; flag.letter.read = true
```

| کار بازیکن | نتیجه |
| --- | --- |
| Read قبل از بازکردن | رد؛ شرط `state.sealed = 0` برقرار نیست |
| Open | مهر باز می‌شود، `flag.letter.opened` روشن |
| Read | `state.read = 1`، `flag.letter.read` روشن، برگه باز می‌شود |

### کلید

```
key.archive | کلید بایگانی | Archive key | key | 1
| unlock.target=door.archive
| unlock.do=flag.door.archive = true
```

`unlock` با هدف دیگر جواب نمی‌دهد؛ همین «کلید، قفل خودش» است.

### کلت

```
weapon.pistol_01 | کلت | Pistol | weapon | 1
| state.ammo=0
| use.if=state.ammo >= 1
| use.do=state.ammo - 1; flag.pistol.fired = true
| reload.if=item.ammo.9mm >= 1
| reload.do=state.ammo = 8
```

بدون فشنگ، `use` رد می‌شود؛ `reload` هم تا فشنگ در جیب نباشد.

### شاهد

```
evidence.casing_01 | پوکه | Bullet casing | evidence | 10
| examine.do=flag.evidence.casing.seen = true
```

## ۴. کلاس‌ها

| فایل | کلاس | کار |
| --- | --- | --- |
| `Items/ItemDefinition.cs` | `ItemDefinition` | تعریف + قاعده‌ها + وضعیت اولیه + مسیر سند |
| `Items/ItemInstance.cs` | `ItemInstance` | نمونه: شناسه‌ی یکتا، تعداد، دوام، `state.*` |
| `Items/ItemRule.cs` | `ItemRule` / `ItemRuleSet` | قاعده و جست‌وجوی قاعده |
| `Items/ItemVerb.cs` | `ItemVerb` / `ItemVerbs` | نام فعل‌ها |
| `Items/ItemState.cs` | `ItemState` | خواندن/نوشتن `state.*` و ساختن دنیای «شده» |
| `Items/ItemCatalog.cs` | `ItemCatalog` | خواندن `items.txt` |
| `Items/ItemRuntime.cs` | `ItemRuntime` | اجرای فعل: قاعده → اثر → نشانه → مصرف → رویداد |
| `Items/ItemContainer.cs` | `ItemContainer` | یک ظرف (جیب، صندوق، زمین) |
| `Items/InventoryManager.cs` | `InventoryManager` | تراکنش‌ها + پروجکشن `item.*` |
| `Items/ItemEvents.cs` | `ItemEvents` | رویدادها برای کارها و رابط |
| `Items/ItemSave.cs` | `ItemSave` | ذخیره و بارگذاری نسخه‌دار |
| `Items/ItemSelfTest.cs` | `ItemSelfTest` | ۱۴ گروه تست داخل بازی |

### جریان یک فعل

```
Perform(instance, verb, target)
  ├─ view = دنیا + state همین نمونه
  ├─ rule = اولین قاعده‌ی این فعل که شرطش برقرار است
  │     ├─ قاعده هست ولی شرطش نه  → ConditionFailed
  │     └─ قاعده نیست و پیش‌فرض هم نیست → NotAllowed
  ├─ اثرها: state.* روی نمونه، بقیه روی دنیا
  ├─ flag.item.<verb>.<id> = true
  ├─ رویداد Performed
  ├─ اگر consume: یک عدد کم
  └─ اگر read و سند: برگه باز می‌شود
```

«نشانه‌ی داستانی» یعنی کارها و دیالوگ‌ها بدون کد گوش می‌دهند:

```
[if] flag.item.read.file.sealed = true
```

## ۵. آیتم تازه

۱. یک خط به `Assets/_Project/Resources/Items/items.txt` اضافه کن.
۲. `python3 tools/itemcheck.py` بزن.
۳. در Unity پنجره‌ی `Tehran Noir/آیتم‌ها` را باز کن و ببین.

## ۶. فعل تازه (به‌ندرت)

اگر فعل کاملاً تازه‌ای خواستی (نه فقط قاعده‌ی تازه):

| قدم | فایل |
| --- | --- |
| ۱ | یک مقدار در `enum ItemVerb` |
| ۲ | یک `case` در `ItemVerbs.TryParse` و `Name` |
| ۳ | اگر پیش‌فرض خاصی دارد، در `ItemDefinition.HasDefault` |

هیچ کلاس آیتم یا دسته‌ای عوض نمی‌شود.

## ۷. کارها و مأموریت‌ها

| راه | چطور |
| --- | --- |
| داده (پیشنهادی) | در فایل کار، شرط روی `flag.item.<verb>.<id>` بگذار |
| کد | `ItemEvents.Performed += handler` و در `OnDisable` لغو کن |
| وضعیت سند | `flag.letter.opened`، `flag.letter.read` (از خود آیتم) |

## ۸. ذخیره

`ItemSave.Capture()` → JSON نسخه‌دار؛ `ItemSave.Restore(json)`.

| ذخیره می‌شود | ذخیره نمی‌شود |
| --- | --- |
| شناسه‌ی ظرف، شناسه‌ی یکتای نمونه | آبجکت صحنه |
| شناسه‌ی تعریف، تعداد، دوام | ScriptableObject |
| همه‌ی کلیدهای `state.*` | اشاره‌گر حافظه |

نسخه‌ی بزرگ‌تر از `CurrentVersion` رد می‌شود؛ شناسه‌ی تکراری در بارگذاری
ساخته نمی‌شود.

## ۹. تست

`ItemSelfTest` را روی یک GameObject خالی بگذار و Play بزن. ۱۴ گروه، جدول
PASS/FAIL در Console:

| گروه | چه چیزی |
| --- | --- |
| تعریف‌ها | بار شدن، سند، قاعده‌ها |
| ساخت | شناسه‌ی یکتا، وضعیت اولیه |
| اضافه/کم | تعداد و پروجکشن `item.*` |
| پشته | تقسیم و ادغام |
| جا | سقف ظرف |
| انداختن | بدون تکرار |
| انتقال | بین دو ظرف |
| سند | مهر → باز → خوانده |
| کلید | قفل درست و غلط |
| سلاح | پر کردن و شلیک |
| رویداد | یک بار، با لغو |
| ذخیره | رفت و برگشت با وضعیت |
| تعریف ناشناس | بدون خطا |
| شناسه‌ی تکراری | رد می‌شود |

## ۱۰. اگر شرطی خوانده نشود چه می‌شود؟

قاعده‌ی آن فعل **حذف** می‌شود و آیتم به رفتار پیش‌فرض پرچم‌ها برمی‌گردد.
در نسخه‌ی اول، شرط‌ها با `=` تنها نوشته شده بودند و `ConditionParser` فقط `==`
را می‌پذیرفت؛ نتیجه:

| نشانه | معنی |
| --- | --- |
| `0` در «قاعده‌ها پارس شدند» | همه‌ی قاعده‌های آن آیتم حذف شده‌اند |
| خواندن سند مهرشده جواب می‌دهد | قاعده‌ی `read` نیست، پس پیش‌فرض «سند = خواندنی» |
| `Open` انجام نمی‌شود | هیچ پیش‌فرضی برای `open` نیست |

دو کار انجام شد: `=` تنها در شرط پذیرفته شد، و `tools/itemcheck.py` حالا
همان گرامر شرط را می‌خواند و شرط خراب را **قبل** از ورود به بازی می‌گیرد.
و اخطار خروجی از Warning به Error تغییر کرد و شناسه‌ی آیتم را می‌گوید.

## ۱۱. ساختن، آزمایش و حذف آیتم (پنجره‌ی ادیتور)

منو: `Tehran Noir/آیتم‌ها`

| دکمه | کار |
| --- | --- |
| فهرست سمت راست | انتخاب آیتم؛ جزئیات در سمت چپ |
| جست‌وجو | شناسه یا نام فارسی/انگلیسی |
| فیلتر دسته | فقط همان دسته |
| بازخوانی | فایل را دوباره می‌خواند (بعد از ویرایش دستی) |
| بررسی داده | تکرار شناسه، دسته/فعل ناشناس، مسیر گم‌شده |
| آیتم تازه + افزودن | یک خط به `items.txt` اضافه می‌کند |
| حذف این آیتم | با تأیید، خط همان شناسه را برمی‌دارد |

حذف فقط خط همان شناسه را برمی‌دارد؛ خط‌های دیگر و توضیح‌ها دست نمی‌خورند.
اگر جایی در دیالوگ یا کار از آن آیتم استفاده شده، آن شرط دیگر برقرار نمی‌شود.

## ۱۲. آزمایش در بازی

| قدم | کار |
| --- | --- |
| ۱ | یک GameObject خالی بساز و `ItemSelfTest` را اضافه کن |
| ۲ | Play؛ در Console جدول PASS/FAIL چاپ می‌شود |
| ۳ | برای دیدن کارت‌ها: Esc → تب «کاراکتر» → «وسایل» |
| ۴ | Enter روی کارت = فعل اصلی (سند → خواندن، بقیه → استفاده/بررسی) |
| ۵ | برای دادن آیتم: `F10` و مقدار `item.<id>` را ست کن |
| ۶ | پنل تست عدد را عوض می‌کند؛ `InventoryManager.Reconcile()` موقع Enter نمونه می‌سازد |

## ۱۳. محدودیت‌ها

| مورد | وضعیت |
| --- | --- |
| اثر شرطی داخل یک قاعده (`if` در `do`) | نیست؛ به‌جایش قاعده‌ی دوم با شماره |
| کم‌کردن آیتم دیگر با اثر | نیست؛ عمداً، تا پروجکشن یک منبع بماند |
| آیکون و Prefab | مسیر پشتیبانی می‌شود؛ هنوز هیچ آیتمی آیکون اختصاصی ندارد |
| پنجره‌ی ادیتور | فهرست/فیلتر/بررسی/افزودن؛ ویرایش درجا ندارد |
| تست خودکار بیرون از Unity | نیست؛ کامپایلر C# در محیط ما وجود ندارد |
