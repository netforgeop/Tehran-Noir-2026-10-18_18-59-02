# ۳۶. فعل‌های آیتم در منو و انداختن روی زمین

تاریخ: ۲۰۲۶-۱۱-۱۲ — جلسه‌ی بیست‌وهشتم

## ۱. مسئله

سیستم آیتم تست‌هایش را پاس کرده بود، ولی دو جا در بازی دیده نمی‌شد:

| مشکل | نتیجه در بازی |
| --- | --- |
| در بخش «وسایل» فقط Enter کار می‌کرد | پرونده‌ی مهرشده را نمی‌شد باز کرد؛ Enter دنبال «خواندن» می‌رفت و رد می‌شد |
| انداختن فقط داده را جابه‌جا می‌کرد | شیئی روی زمین ظاهر نمی‌شد؛ آیتم عملاً گم می‌شد |

## ۲. فعل‌ها در بخش «وسایل»

### چیدمان

نوار فعل‌ها زیر خط شرح می‌نشیند (`y=620` نسبت به بالای ستون محتوا)، چهار خانه‌ی
۲۱۴ پیکسلی با فاصله‌ی ۱۲. در فارسی از راست شروع می‌شود، در انگلیسی از چپ.

| عنصر | جزئیات |
| --- | --- |
| بج عدد | ۳۲ پیکسل، عدد فارسی، طلایی |
| متن فعل | از `Loc`، کلید `item.verb.<verb>` |
| خانه‌ی اول | قاب طلایی: فعل اصلی (همان که Enter می‌زند) |
| بقیه | قاب خاکستری |

### کدام فعل‌ها نشان داده می‌شوند

`ItemDefinition.Verbs(view, target, results)` فهرست `ItemVerbs.Ordered` را
می‌گیرد و هر فعلی را که `CanDo` رد کند حذف می‌کند. یعنی:

| آیتم | وضعیت | فعل‌ها |
| --- | --- | --- |
| پرونده‌ی مهرشده | مهر بسته | بررسی · **باز کردن** · انداختن |
| پرونده‌ی مهرشده | مهر باز | بررسی · **خواندن** · انداختن |
| کلت | خشاب ۰ | بررسی · تجهیز · انداختن |
| کلت | خشاب ۸ و فشنگ در جیب | بررسی · **استفاده** · پر کردن · انداختن |
| سیگار | — | بررسی · **استفاده** · انداختن |

پس هیچ فعل غیرممکنی نشان داده نمی‌شود و نوار با عوض شدن وضعیت خودش عوض می‌شود.

### کلیدها

| کلید | کار |
| --- | --- |
| `۱` تا `۵` | فعل همان شماره |
| `Enter` / `Space` | فعل اصلی (خانه‌ی طلایی) |
| کلیک روی خانه | همان فعل |
| `W/S` `A/D` | جابه‌جایی روی کارت‌ها و نوار دسته |

مسیر کد: `PauseMenuUI.HandleOpenInput` → `PauseTab.Digit(int)` →
`CharacterPauseTab.Digit` → `CharacterItemsSection.Digit`.

## ۳. انداختن روی زمین

| جزء | کار |
| --- | --- |
| `InventoryManager.Drop` | آیتم را به ظرف `world` می‌برد و رویداد `Dropped` می‌دهد |
| `ItemDropSpawner` | به `Dropped` گوش می‌دهد، آبجکت می‌سازد، `WorldItemPickup` را وصل می‌کند |
| `WorldItemPickup` | با «برداشتن» همان نمونه را به جیب برمی‌گرداند و خودش را حذف می‌کند |

### چرا همان نمونه؟

اگر هنگام برداشتن، نمونه‌ی تازه ساخته می‌شد، سندی که مهرش باز شده بود با مهر
بسته برمی‌گشت و شناسه‌ی یکتایش عوض می‌شد. `WorldItemPickup` همان `ItemInstance`
را نگه می‌دارد و `InventoryManager.Move` را صدا می‌زند؛ پس حالت (مهر، خوانده‌شدن،
خشاب) دست‌نخورده می‌ماند.

### ظاهر

| حالت | چه ساخته می‌شود |
| --- | --- |
| آیتم `prefab=` دارد | همان Prefab |
| ندارد | مکعب کوچک ۰٫۱۸ متری با رنگ برنجی مات |

پس تا وقتی مدل‌های سه‌بعدی آماده نیستند، بازی کار می‌کند.

## ۴. تنظیم در صحنه (دیگر لازم نیست)

`ItemDropSpawner.Ensure()` خودش میزبان را می‌سازد:

| کِی | چه می‌شود |
| --- | --- |
| اولین انداختن | اگر شنونده‌ای نباشد، `Item Drops` ساخته و مشترک می‌شود |
| بازیکن پیدا شد | شیء ۰٫۹ متر جلوتر، روی زمین (با Raycast) |
| بازیکن پیدا نشد | هشدار در Console، بدون ساختن شیء |

اگر خودت کامپوننت را روی `Player` بگذاری هم قبول است؛ نسخه‌ی دومی ساخته نمی‌شود.

### علت اصلی «انداختن کار نکرد»

`ItemSelfTest.Run()` در `finally` این خط را داشت:

```csharp
ItemEvents.ClearAll();
```

این خط **همه‌ی** مشترک‌ها را پاک می‌کرد، از جمله `ItemDropSpawner`. چون تست با
`Run On Start` قبل از شروع بازی اجرا می‌شد، انداختن تا آخر آن Play بی‌اثر می‌ماند.
حالا تست فقط مشترکِ خودش را برمی‌دارد و یک تست تازه (`مشترکِ بیرونی بعد از تست زنده می‌ماند`)
همین را تضمین می‌کند.

## ۵. تست‌های تازه

`ItemSelfTest` از ۳۶ به **۴۶** رسید:

| تست | چه چیزی |
| --- | --- |
| سند مهرشده: «باز کردن» هست | فهرست فعل از قاعده‌ی `open` |
| سند مهرشده: «خواندن» نیست | شرط `state.sealed = 0` برقرار نیست |
| بعد از بازکردن: «خواندن» اضافه شد | فهرست با وضعیت عوض می‌شود |
| کلت خالی: «استفاده» نیست، «بررسی» هست | قاعده‌ی `use` شرطی است |
| افتادن در ظرف زمین | `ContainerId == world` |
| برداشتن دوباره | `Move` موفق |
| همان نمونه برگشت | `InstanceId` یکی است |
| حالت سند بعد از رفت‌وبرگشت | مهر باز مانده |
| مشترکِ بیرونی بعد از تست زنده می‌ماند | `ClearAll` حذف شده |
| کلت: «مصرف» و «جدا کردن» بی‌دلیل نیستند | پیش‌فرض این دو فعل حذف شد |

## ۶. نام آیتم بعد از تغییر وضعیت

گزارش: «پرونده را باز کردم، باز هم نوشته مهرشده.»

علت: نام کارت از تعریف ثابت می‌آمد (`ItemDefinition.Name`)، در حالی که باز شدن
مهر فقط `state.sealed` را عوض می‌کرد. دو چیز جدا بودند و هیچ‌کدام دیگری را
نمی‌دید.

اصلاح: نام هم مثل فعل‌ها داده‌ای شد.

| جزء | کار |
| --- | --- |
| `title.if` / `title.fa` / `title.en` (+ شماره) | نام جایگزین با شرط |
| `ItemDefinition.Title(view, persian)` | آخرین نامی که شرطش برقرار است (دقیق‌تر مقدم) |
| `ItemRuntime.Title(instance, persian)` | همان، با دنیای «شده»ی همین نمونه |
| `CharacterItemsSection` | کارت، خط شرح و نوار فعل از همین می‌خوانند |
| `WorldItemPickup.Title` | کارت تعامل روی زمین هم همین را می‌گوید |

یعنی پرونده در سه حالت سه نام دارد: «پرونده‌ی مهرشده» → «پرونده‌ی بازشده» →
«پرونده‌ی خوانده‌شده».

## ۷. تغییر مهم در پرچم‌ها

پیش‌فرض «همه‌ی اجازه‌ها» باعث می‌شد پوکه و فشنگ هم دکمه‌ی «استفاده» بگیرند.
حالا دو مجموعه داریم:

| مجموعه | شامل |
| --- | --- |
| `Common` (پیش‌فرض وقتی `flags` نوشته نشده) | انداختن، معامله، انبار، بررسی، نابودی |
| `All` (فقط با `flags=all`) | همه‌ی بالا + استفاده + تجهیز |

پس «استفاده» و «تجهیز» باید صریح نوشته شوند — یا قاعده‌ی `use.do` وجود داشته باشد.

## ۸. محدودیت‌ها

| مورد | وضعیت |
| --- | --- |
| انداختن در حالت توقف | شیء ساخته می‌شود، ولی تا بستن منو دیده نمی‌شود |
| ذخیره‌ی اشیای زمین | آبجکت‌های زمین ذخیره نمی‌شوند؛ نمونه‌ها در ظرف `world` می‌مانند |
| انتخاب هدف کلید | «باز کردن قفل» از جیب کار نمی‌کند؛ به هدف نیاز دارد (در تعامل در) |
| مدل سه‌بعدی | پیش‌فرض مکعب؛ با `prefab=` عوض می‌شود |
