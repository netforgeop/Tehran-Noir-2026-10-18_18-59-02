# ۴۸ — برش ساختمان: از بیرون کامل، از داخل یک طبقه

## ۱. مشکل در یک تصویر

در `Hilton814.unity` صفحه‌ی بازی این بود: یک توده‌ی قهوه‌ای که دو سوم تصویر را
گرفته، و بازیکن جایی بیرون از کادر. هیچ خطایی در Console نبود. پرونده سالم
بود؛ **دید** خراب بود.

علت با یک محاسبه روشن شد. دوربین این بازی سینم‌مشین است:

```text
CinemachineOrbitalFollow
  Orbits.Top     Radius 2    Height 5
  Orbits.Center  Radius 4    Height 2.25
  VerticalAxis.Value = 50    (قفل، بدون چرخش عمودی)
```

یعنی دوربین حدود سه متر عقب‌تر و سه متر بالاتر از بازیکن است. بازیکن روی زمین
است، پس دوربین حدود چهار متر بالاتر از زمین است. سقفِ راهرو در ارتفاع
دو و شش دهم است. **دوربین بالای سقف بود و به سقف نگاه می‌کرد.** توده‌ی قهوه‌ای
همان دالِ سقف بود.

## ۲. قاعده، در دو خط

```text
بیرون از ساختمان  → همه‌چیز روشن. ساختمان کامل دیده می‌شود.
داخلِ طبقه‌ی n    → طبقه‌های بالاتر از n خاموش، و سقفِ خودِ n هم خاموش.
```

سقفِ هر طبقه، کفِ طبقه‌ی بالاست. پس با خاموش‌کردن طبقه‌ی بالایی، سقف خودش
می‌رود. این همان چیزی است که سیمز و پروجکت زامبوید می‌کنند: نه سوراخ‌کردن
سقف، بلکه برداشتنِ طبقه‌های بالایی و دیدنِ داخل.

## ۳. دو کامپوننت

```text
Assets/_Project/Scripts/World/CutawayPiece.cs
```

روی هر تکه‌ی ساختمان. دو فیلد:

| فیلد | معنی |
| --- | --- |
| `role` | `Floor` = خودِ این طبقه · `Ceiling` = سقفِ بالای همین طبقه |
| `level` | شماره‌ی طبقه؛ لابی صفر است |

```csharp
public bool IsVisibleAt(int currentLevel)
{
    if (role == CutawayRole.Ceiling)
        return level > currentLevel;

    return level <= currentLevel;
}
```

```text
Assets/_Project/Scripts/World/BuildingCutaway.cs
```

روی **ریشه‌ی ساختمان**. یک `GetComponentsInChildren` می‌زند و همه‌ی تکه‌ها را
جمع می‌کند؛ بعد هر یک دهم ثانیه یک بار حساب می‌کند بازیکن داخل است یا بیرون و
در کدام طبقه، و فقط وقتی جواب عوض شد رندررها را روشن و خاموش می‌کند.

| فیلد | معنی |
| --- | --- |
| `viewer` | بازیکن؛ خالی بماند خودش پیدایش می‌کند |
| `interiorCenter`, `interiorSize` | جعبه‌ی داخلی ساختمان |
| `exitMargin` | چند متر بیرون بروی تا «بیرون» حساب شود |
| `floorHeight`, `groundLevel` | طبقه از ارتفاع حساب می‌شود |

**فقط `Renderer.enabled` عوض می‌شود.** کولایدرها دست نمی‌خورند: اگر کولایدر
سقف هم خاموش شود، بازیکن از طبقه‌ای که سقفش برداشته شده می‌افتد بیرون. کولایدرِ
نامرئی هیچ ضرری به تصویر نمی‌زند.

## ۴. چرا مدیر باید روی ریشه باشد

اولین نسخه، کامپوننت را روی یک آبجکت خالیِ تازه به نام `BuildingCutaway` گذاشت
که فرزندِ ریشه بود. نتیجه:

```text
GetComponentsInChildren<CutawayPiece>()  →  صفر
```

و صفر یعنی هیچ کاری نمی‌شود، بی هیچ خطایی. برای همین الان:

- مدیر با `attach_component` روی خودِ ریشه می‌نشیند.
- اگر تکه‌ای پیدا نشود، یک `Debug.LogWarning` می‌نویسد.
- گام دهم `preflight` همین را بیرون از یونیتی چک می‌کند:
  `tools/cutawaycheck.py`.

## ۵. دو صحنه‌ای که عوض شدند

### الف) `Scenes/Hilton.unity` — خیابان و ساختمان کامل

قبلاً یک اتاق بی‌سقف بود. حالا:

```text
   بام  ──  پاراپت، تانک آب، اتاقِ پله
   طبقه ۳ ──  دال + نوار دیوار + شیشه
   طبقه ۲
   طبقه ۱ ──  تابلوی نئون بالای سایبان
   ────────────────────────────────
   لابی   ──  پیشخوان، صندوق، صندوق‌دار، دو کاغذ
   ────────────────────────────────
   سایبان ──  ستون، دو لنگه درِ باز
   پیاده‌رو ──  جدول، ماشین پارک‌شده، دو چراغ خیابان
   خیابان  ──  آسفالت، بلوکِ روبه‌رو با پنجره‌های روشن
```

بازیکن روی آسفالت به دنیا می‌آید. ساختمان کامل است. تا وقتی از پیاده‌رو رد
نشده، هیچ‌چیز پنهان نیست. از آستانه که رد شد، طبقه‌های یک تا سه و بام خاموش
می‌شوند و لابی از بالا دیده می‌شود.

| آبجکت | نقش |
| --- | --- |
| `HiltonBuilding` | ریشه؛ `BuildingCutaway` روی خودش |
| `Lobby` | تکه‌ی `Floor`، سطح ۰ — پنجاه فرزند |
| `Floor_1`, `Floor_2`, `Floor_3` | تکه‌های `Floor`، سطح ۱ تا ۳ |
| `Roof` | تکه‌ی `Floor`، سطح ۴ |
| `Sidewalk`, `Road`, `Car_*`, `Street_Lamp_*` | خیابان — همیشه روشن |
| `Sign_Box`, `Sign_Glow`, `Light_Sign` | تابلوی نئون شبانه |

درِ شیشه‌ایِ بسته‌ی قبلی برداشته شد؛ با آن، بازیکن هرگز نمی‌توانست از خیابان
وارد شود. حالا یک بازشوی سه متری با دو لنگه‌ی باز است.

### ب) `Scenes/Hilton814.unity` — سقفِ همان تصویر

سه سقف — راهرو، اتاق ۸۱۴، دفتر مدیر — تکه‌ی `Ceiling` سطح ۰ گرفتند. با شروع
صحنه پنهان می‌شوند و همان توده‌ی قهوه‌ای دیگر نیست.

## ۶. چطور ساختمان تازه بسازی

```python
root_id, root = kit.empty(builder, "Building", parent)
kit.building_cutaway(builder, root_id, viewer, center, size,
                     floor_height=3.0, ground_level=0.0)

lobby, lobby_root = kit.empty(builder, "Lobby", root)
kit.cutaway_piece(builder, lobby, 0, 0)      # Floor، سطح ۰

first, first_root = kit.empty(builder, "Floor_1", root)
kit.cutaway_piece(builder, first, 0, 1)      # Floor، سطح ۱
```

سه قاعده:

1. تکه‌ها **فرزندِ مستقیمِ ریشه** باشند، نه تودرتو.
2. جعبه‌ی داخلی فقط فضای داخلی را بگیرد، نه پیاده‌رو.
3. سقفِ دست‌ساز (مثل راهروی ۸۱۴) تکه‌ی `Ceiling` بگیرد؛ سقفی که خودش دالِ
   طبقه‌ی بالاست، لازم ندارد.

می‌نویسد.

## ۸. محدودیت‌ها

- **در Unity بازی نشده.** قاعده با ابزار بیرونی و تستِ زمان اجرا بررسی شده،
  ولی چشمِ آدم هنوز آن را ندیده.
- **ساختمان از داخل سقف دارد، ولی بازیکن فقط لابی است.** اگر بعداً پله به
  طبقه‌ی دوم اضافه شود، همان قاعده بی تغییر کار می‌کند: طبقه از ارتفاع حساب
  می‌شود.
- **دیوارهای طبقه‌ی جاری بریده نمی‌شوند.** سیمز دیوارِ نزدیک به دوربین را هم
  نصف می‌کند. آن یک قدم بعدی است؛ الان سقف و طبقه‌های بالا می‌روند.
- **برش با محو شدن همراه نیست.** رندرر یک‌باره خاموش می‌شود. برای عبور از
  آستانه کافی است، برای گذرِ پله نه.
