# ۲۱ — پرونده: باز کردن یا برداشتن

## ۱. تصمیم معماری

تا امروز هر آبجکت **یک** کار داشت. پرونده دو کار دارد و همین، اولین شکاف واقعی بود:

| آبجکت | کارها |
| --- | --- |
| رضا | صحبت |
| کمد | باز کردن |
| پرونده | **باز کردن · برداشتن** |

جای اینکه برای پرونده یک کلاس جدا با منطق موازی بسازیم، خودِ `Interactable` فهرست کار گرفت:

```csharp
public virtual IReadOnlyList<InteractionAction> Verbs   // پیش‌فرض: یک کار
public virtual void Interact(GameObject interactor, InteractionAction verb)
```

سنسور همیشه نسخه‌ی دوتایی را صدا می‌زند و کار انتخاب‌شده را می‌دهد. کلاس‌هایی که یک کار دارند هیچ چیزشان عوض نمی‌شود؛ فقط آبجکت‌های چندکاره تابع `Verbs` را عوض می‌کنند.

## ۲. پرونده

`FileInteractable` از `PickupInteractable` ارث می‌برد، چون برداشتنش همان برداشتن هر چیز دیگر است: شرط ظهور، ناپدید شدن، نوشتن در `WorldState`. روی آن، یک چیز اضافه می‌کند: **باز کردن**.

| کار | اثر |
| --- | --- |
| باز کردن | `flag.file.opened = true` + پخش `file_sealed.txt` |
| برداشتن | `flag.file.taken = true` + ناپدید شدن |

بعد از باز شدن، «باز کردن» از فهرست حذف می‌شود؛ باز کردن دوباره معنی ندارد.

## ۳. رابط کاربری

کارت حالا ارتفاعش را با تعداد کارها حساب می‌کند:

```text
┌──────────────────────────────────────┐
│ 1. باز کردن              (روشن)   [E]│
│ 2. برداشتن              (خاموش)      │
│ پرونده محرمانه                       │
│ مهر و موم‌شده                        │
│ کلید ۱ تا ۳: انتخاب کار              │
└──────────────────────────────────────┘
```

- `1` تا `3` کار را انتخاب می‌کند.
- `E` کار انتخاب‌شده را اجرا می‌کند.
- چرخ موس همان‌طور بین **اهداف** نزدیک می‌چرخد، نه کارها. دو محور جدا، بدون تداخل.
- یک کار = همان کارت کوچک قبلی، بدون فضای خالی.

## ۴. محتوای پرونده

`Assets/_Project/Dialogue/file_sealed.txt` — پنج خط، با پنل دیالوگ فعلی خوانده می‌شود (صفر کد تازه):

```text
صورت‌جلسه‌ی بازجویی. ۱۴ مرداد ۱۳۵۲.
متهم: کریم شریفی، بیست‌وشش ساله، راننده.
بازداشت در خیابان ری، ساعت دو بامداد.
علت مرگ: نامشخص. پرونده بسته شد.
امضا: سرگرد یزدانی.
```

این یعنی باز کردن پرونده **ارزش دارد**: اسم یک آدم، یک مرگ مشکوک، و امضای کسی که بالادست رضاست.

## ۵. تنظیم در Unity

**۱. پرونده**

`File` را انتخاب کن. کامپوننت `Pickup Interactable` را **حذف** کن (اگر داری) و جایش `File Interactable` بگذار. مقدارها همان‌ها می‌مانند:

| فیلد | مقدار |
| --- | --- |
| Display Name | `پرونده محرمانه\|Confidential file` |
| Subtype | `مهر و موم‌شده\|Sealed` |
| Require Variable | `flag.quest.file` |
| Require Value | `1` |
| Taken Variable | `flag.file.taken` |

**۲. خواننده‌ی محتوا**

روی همان `File` یک کامپوننت `Dialogue Starter` اضافه کن:

| فیلد | مقدار |
| --- | --- |
| Dialogue File | `file_sealed` |
| Start Node Id | خالی |
| Dialogue UI | همان `DialogueSystem` صحنه |

سپس در `File Interactable` فیلد `Content Reader` را با همین `Dialogue Starter` پر کن (یا خالی بگذار؛ خودش روی همان آبجکت پیدا می‌کند).

**۳. `Ctrl + S`، بعد `Play`.**

## ۶. آزمایش

۱. رضا کار را بدهد → پرونده روی میز ظاهر شود.
۲. نزدیک میز: کارت **دو ردیف** دارد: «۱. باز کردن» و «۲. برداشتن».
۳. `2` را بزن: ردیف دوم روشن می‌شود. `E` → پرونده برداشته می‌شود، بدون خواندن.
۴. `Play` را قطع کن، دوباره برو و این بار `1` → `E`: پنل دیالوگ با متن پرونده باز می‌شود و `flag.file.opened` روشن می‌شود.
۵. بعد از باز کردن، کارت **فوراً** عوض می‌شود و «۱. خواندن» و «۲. برداشتن» نشان می‌دهد.
   «خواندن» دوباره برگه را باز می‌کند و هیچ چیزی در دنیا عوض نمی‌کند.

## ۶.۱. چرا کارت باید فوری عوض شود

`InteractionHUD` قبلاً فقط وقتی آبجکت هدف عوض می‌شد کارت را بازمی‌ساخت.
اما فهرست کارهای یک آبجکت هم می‌تواند عوض شود (پرونده بعد از باز شدن)، بدون اینکه هدف عوض شود.
نتیجه: کارت «باز کردن» را نشان می‌داد در حالی که فهرست واقعی «خواندن / برداشتن» بود؛
`E` آن‌وقت کار اشتباهی می‌زد (یا هیچ کاری) و کاربر فکر می‌کرد سیستم خراب است.

حالا HUD هر فریم **اثر انگشت فهرست کارها** را حساب می‌کند (`VerbSignature`) و با تغییرش
کارت را از نو می‌سازد. قاعده برای هر `Interactable` تازه: `Verbs` باید فقط از روی وضعیت
دنیا حساب شود و همان لحظه درست بگوید چه کاری ممکن است.
