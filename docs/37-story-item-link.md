# ۳۷. اتصال پرونده‌ی داستان به سیستم آیتم

تاریخ: ۲۰۲۶-۱۱-۱۲ — جلسه‌ی سی‌ویکم

## ۱. مسئله

سیستم آیتم در سندباکس کار می‌کرد، ولی پرونده‌ی داستان دو واقعیت جدا داشت:

| جای واقعیت | چه چیزی را می‌دانست |
| --- | --- |
| آبجکت روی میز (`FileInteractable`) | یک بولی `_opened` در حافظه‌ی همان کامپوننت |
| جیب بازیکن (`InventoryManager`) | یک `ItemInstance` تازه که از `state.sealed` بی‌خبر بود |

و بدتر: نام پرچم‌ها هم یکی نبود.

| نوشته می‌شد | خوانده می‌شد |
| --- | --- |
| `flag.letter.opened` | `flag.file.opened` |
| `flag.letter.read` | `flag.file.taken` |

دیالوگ‌های `reza_office.txt` و `farhadi_archive.txt` و قدم‌های `case_file.txt` همه
`flag.file.*` را می‌خواندند؛ پس حتی اگر آیتم مهر را باز می‌کرد، داستان نمی‌فهمید.

## ۲. اصلاح یک: یک واقعیت، نه دو

`SceneItemBinding` اضافه شد.

| کِی | چه می‌شود |
| --- | --- |
| `Awake` آبجکت | یک نمونه‌ی آیتم به همان آبجکت وصل می‌شود |
| برداشتن | `InventoryManager.Move` همان نمونه را به جیب می‌برد |
| باز کردن | `ItemRuntime.Perform(instance, Open)` → `state.sealed = 0` |
| خواندن | `ItemRuntime.Perform(instance, Read)` → `state.read = 1` |
| برداشتن دوباره از زمین | همان نمونه برمی‌گردد |

پیوند در حافظه است و در فایل ذخیره نمی‌نوشت؛ هر بار که صحنه بار شود، آبجکت
نمونه‌ی خودش را می‌گیرد.

## ۳. اصلاح دو: نام پرچم‌ها

`items.txt` حالا همان نام‌هایی را می‌نویسد که داستان می‌خواند:

| کِی | چه نوشته می‌شود |
| --- | --- |
| برداشتن (`ontake.do`) | `flag.file.taken = true` |
| انداختن (`ondrop.do`) | `flag.file.taken = false` |
| باز کردن مهر | `flag.file.opened = true` |
| خواندن | `flag.file.read = true` |

`flag.file.read` تازه است و هنوز جایی خوانده نمی‌شود؛ برای قدم بعدی داستان.

## ۴. کارت تعامل

| قبل | بعد |
| --- | --- |
| نام از `Display Name` دستی | از `ItemRuntime.Title` → «پرونده‌ی مهرشده» / «پرونده‌ی بازشده» |
| فعل‌ها از `_opened` کامپوننت | از `state.sealed` خودِ نمونه |

## ۵. تست‌های تازه (۵۳ تست)

| تست | چه چیزی را تضمین می‌کند |
| --- | --- |
| برداشتن پرونده: `flag.file.taken` | قرارداد با `case_file.txt` |
| باز کردن: `flag.file.opened` | قرارداد با `reza_office.txt` |
| خواندن: `flag.file.read` | پرچم تازه‌ی داستان |
| شرط داستان با پرچم آیتم جواب می‌دهد | `ConditionParser.Parse("flag.file.taken == true")` |

## ۶. محدودیت‌ها

| مورد | وضعیت |
| --- | --- |
| برگرداندن پرونده در بایگانی | دیالوگ `flag.file.taken = false` می‌کند ولی آیتم را از جیب برنمی‌دارد |
| دو آبجکت با یک شناسه‌ی آیتم | هر کدام نمونه‌ی خودش را می‌گیرد؛ پیوند بر اساس شناسه‌ی نمونه است |
| ذخیره‌ی موقعیت آبجکت‌های صحنه | نیست؛ نمونه‌ها در ظرف `world` می‌مانند |

### قدم بعدی که این را کامل می‌کند

یک اثر دیالوگی برای «تحویل دادن»: وقتی دیالوگ می‌گوید پرونده تحویل داده شد،
همان نمونه از جیب بازیکن به ظرف بایگانی منتقل شود. تا آن نباشد، بعد از تحویل
هم کارت پرونده در «وسایل» می‌ماند.
