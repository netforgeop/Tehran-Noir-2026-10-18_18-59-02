# ۳۲. جیب — بخش «وسایل» تب کاراکتر

تاریخ: ۲۰۲۶-۱۱-۱۲ — جلسه‌ی بیستم

## ۱. تصمیم

بخش «وسایل» در تب کاراکتر از یک پیام «بعداً» به فهرست واقعی تبدیل شد.
فهرست، **هیچ عددی از خودش ندارد**: تعداد هر آیتم همان متغیر `item.<id>` در
`WorldState` است.

| چرا WorldState؟ | نتیجه |
| --- | --- |
| دیالوگ‌ها از قبل با `[if]` / `[do]` کار می‌کنند | `[if] item.file.sealed >= 1` بدون کد تازه کار می‌کند |
| پنل تست (F10) همان متغیرها را نشان می‌دهد | تست بدون ساختن منوی جدید |
| یک منبع حقیقت | دو نسخه‌ی تعداد که از هم جدا شوند وجود ندارد |

## ۲. فایل آیتم‌ها

`Assets/_Project/Resources/Items/items.txt`

```
id | فارسی | انگلیسی | نوع | بیشترین تعداد
```

| قاعده | رفتار |
| --- | --- |
| خط خالی و خطی که با `#` شروع شود | رد می‌شود |
| کمتر از ۴ فیلد | هشدار + رد؛ بازی نمی‌خوابد |
| شناسه با فاصله یا خالی | هشدار + رد |
| شناسه با حرف بزرگ | به حروف کوچک تبدیل می‌شود (`File.Sealed` = `file.sealed`) |
| تکرار شناسه | اولی می‌ماند، دومی هشدار می‌گیرد |
| فیلد پنجم خالی یا خراب یا صفر | بیشترین تعداد = ۱ |
| نوع ناشناس | `item` |
| BOM اول فایل | حذف می‌شود |

نوع‌ها: `document` (سند)، `key` (کلید)، `item` (بقیه).

آیتم تازه = **یک خط** در همین فایل. هیچ کلاسی عوض نمی‌شود.

## ۳. کلاس‌ها

| کلاس | کار |
| --- | --- |
| `ItemDefinition` | شناسه، نام دوزبانه، نوع، بیشترین تعداد |
| `ItemCatalog` | خواندن فایل، `Get(id)`، `All`؛ شناسه‌ی ناشناس هم تعریف جایگزین می‌گیرد |
| `Inventory` | `Count / Has / Room / Add / Remove / Take / Slots / Signature` |
| `InventorySlot` | یک ردیف آماده برای نمایش |

`Take` همه‌یا‌هیچ است: اگر به اندازه‌ی کافی نباشد، هیچ چیز کم نمی‌شود.
`Add` و `Remove` تعداد واقعیِ انجام‌شده را برمی‌گردانند.

## ۴. برداشتن آیتم

`PickupInteractable` دو فیلد تازه دارد: `Item Key` و `Item Count`.
اگر جیب جا نداشته باشد، **شیء برداشته نمی‌شود** و همان‌جا می‌ماند؛
وگرنه آیتم برای همیشه گم می‌شد.

در صحنه، همان `Cube` پرونده‌ی محرمانه از قبل `file.sealed` گرفته است.

## ۵. چیدمان بخش

بخش وسایل از نسخه‌ی ردیفی به شبکه‌ی کارت تبدیل شد؛ جزئیات در `docs/33-items-grid.md`.

## ۶. تازه‌سازی

`Inventory.Signature()` جمع وزن‌دار تعدادهای فهرست است. هر فریم که منو باز
است و بخش وسایل جلوی چشم است، امضا خوانده می‌شود؛ فقط اگر عوض شده باشد
ردیف‌ها دوباره ساخته می‌شوند. تغییر دستی در F10 هم همین‌جا دیده می‌شود.

## ۷. آزمایش

| گام | انتظار |
| --- | --- |
| `Esc` → کاراکتر → `E` (وسایل) | اگر چیزی نداری: «جیبت خالی است» |
| مأموریت پرونده را بگیر، برو سر میز، `E` | شیء ناپدید و «پرونده‌ی مهرشده ۱» در فهرست |
| دوباره همان شیء | چیزی نیست؛ شیء یک بار برداشته می‌شود |
| `F10` → دنیا → `item.cigarettes` = ۳۰ | در تب ۲۰ نشان داده می‌شود (سقف) |
| `F10` → `item.file.sealed` = ۰ | ردیف از فهرست می‌رود |
| زبان انگلیسی | `Sealed file` / `Archive key` / `Cigarettes` |
| ستاره‌ها/سپرها | دست‌نخورده؛ بخش خلاصه با `Q` برمی‌گردد |

> **به‌روزرسانی (جلسه ۲۴):** قالب پنج‌ستونی بالا هنوز معتبر است، ولی ستون ششم و
> گزینه‌های `key=value` اضافه شدند. جزئیات در `docs/34-item-framework.md`.
