# ۳۱. ترتیب عدد در متن فارسی

تاریخ: ۲۰۲۶-۱۱-۱۲ — جلسه‌ی نوزدهم

## ۱. نشانه

«۱ فروردین ۱۳۵۲ — ۰۸:۲۷» روی صفحه «۱۳۵۲» درست بود ولی ساعت «۲۷:۰۸» می‌شد.

## ۲. ریشه

کتابخانه‌ی RTLTMPro رقم فارسی را **حرف راست‌به‌چپ** حساب می‌کند
(`TextUtils.IsArabicCharacter` بازه‌ی 0x600–0x6FF را پوشش می‌دهد و رقم فارسی
0x6F0–0x6F9 داخل همان بازه است). نتیجه:

| مرحله | رفتار |
| --- | --- |
| `LigatureFixer` رقم را می‌بیند | «حرکت راست‌به‌چپ» → رشته‌ی چپ‌به‌راست را می‌شکند |
| `08:27` | «۰۸» و «۲۷» دو تکه‌ی جدا می‌شوند |
| هر تکه جدا وارونه | `۲۷:۰۸` |

عدد پول (`4,500`) و تاریخ (`1352/01/01`) هم همین مشکل را داشتند.

## ۳. سه وصله در کتابخانه

| محل | وصله |
| --- | --- |
| `LigatureFixer` | علامتی که **بین دو رقم** است (دونقطه، ممیز، اسلش) داخل همان رشته‌ی چپ‌به‌راست می‌ماند |
| `LigatureFixer` | علامت **آخر جمله** در متن فارسی سمت چپ می‌نشیند (نقطه‌ی «صفحه‌ی ۴۱.») |
| `TextUtils.IsRTLInput` | وجود **هر** حرف راست‌به‌چپ کافی است، نه فقط اولین حرف |

وصله‌ی سوم برای متن مختلط است: «Esc یا E: بستن» با E شروع می‌شد، پس کل رشته
پردازش نمی‌شد و فارسی‌اش وارونه می‌ماند.

## ۴. عدد خالص

`RTLTextMeshPro` متنی را که هیچ حرفی ندارد دست‌نخورده رد می‌کند، پس «50»
تبدیل نمی‌شد. `UiKit.ForceFixNumbers(text, on)` پرچم `ForceFix` را روشن می‌کند.
جای‌های استفاده: مقدار ویژگی‌ها، برگه‌ی HUD، ردیف تنظیمات (FPS، صدا).

**قاعده‌ی پروژه:** عدد را همیشه ASCII بنویس؛ تبدیل و جهت‌دهی کار کتابخانه است.

## ۵. سنجش

خروجی موتور با یک پیاده‌سازی مرجع الگوریتم دوجهته (پکیج `python-bidi`)
روی ۷۹ رشته‌ی واقعی پروژه مقایسه شد: **۰ اختلاف** پس از یکسان‌سازی رقم‌ها.

| متن | خروجی |
| --- | --- |
| `کارآگاه · 1 فروردین 1352 — 08:27` | `۰۸:۲۷ — ۱۳۵۲ نیدرورف ۱ · هاگآراک` |
| `4,500 تومان` | `ناموت ۴,۵۰۰` |
| `صفحه‌ی 41.` | `.۴۱ یهحفص` |
| `1352/114 — پرونده` | `هدنورپ — ۱۳۵۲/۱۱۴` |

## ۶. آزمایش

| گام | انتظار |
| --- | --- |
| `Esc` → کاراکتر | ساعت `۰۸:۲۷` (نه `۲۷:۰۸`) |
| خط تاریخ | سال و ماه و روز درست |
| پول در برگه‌ی HUD | `۴,۵۰۰` |
| تنظیمات → FPS | `۶۰` |
| سند باز → راهنمای پایین | «برای بستن Esc یا E» درست چیده شده |
