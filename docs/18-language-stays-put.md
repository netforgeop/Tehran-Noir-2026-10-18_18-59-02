# ۱۸ — تغییر زبان نباید منو را بپراند

## چه اتفاقی می‌افتاد

`Loc.Set()` بلافاصله رویداد `Changed` را صدا می‌زند و منو کل رابط را از نو می‌سازد (چون فونت و متن‌ها عوض می‌شوند). ولی صفحه‌ی تنظیمات هم با همان بازسازی دور ریخته می‌شد و نسخه‌ی تازه از **بخش ۰ (صدا)** شروع می‌کرد.

برای کاربر یعنی: یک گزینه‌ی زبان را عوض می‌کنی، منو یک لحظه خالی می‌شود و می‌پری توی «صدا».

## درمان

هر تب حالا می‌تواند وضعیت داخلی‌اش را قبل از بازسازی تحویل بدهد و بعد از آن پس بگیرد:

```csharp
public virtual object SaveState() => null;
public virtual void LoadState(object state) { }
```

تب تنظیمات، بخش و ردیف را در یک شیء کوچک نگه می‌دارد:

```csharp
private sealed class SettingsState
{
    public int Section;
    public int Row;
}
```

`PauseMenuUI.Rebuild()` قبل از خراب‌کردن رابط `SaveState()` را می‌گیرد و بعد از ساخت دوباره `LoadState()` را صدا می‌زند. منوی اصلی هم همین کار را با `SectionIndex` و `SelectedIndex` می‌کند.

نتیجه: زبان عوض می‌شود، فونت و متن‌ها تازه می‌شوند، ولی کاربر سر جایش می‌ماند — در بخش زبان، روی همان ردیف.

## چرا این‌طور، نه با نگه‌داشتن شیء قدیمی

بازسازی لازم است چون `TMP_FontAsset` و جهت متن در لحظه‌ی ساخت ست می‌شوند. نگه‌داشتن شیء قدیمی یعنی باید تک‌تک متن‌ها فونت و جهت تازه بگیرند — کدِ بیشتر و خطای بیشتر. یک تابع دو خطی `SaveState/LoadState` ساده‌تر و برای تب‌های بعدی هم قابل استفاده است.

## آزمایش

۱. `MainMenu` → تنظیمات → زبان: زبان منو را عوض کن.
۲. باید همان بخش «زبان» و همان ردیف بماند؛ فقط متن‌ها و فونت عوض شوند.
۳. داخل بازی `Esc` → تنظیمات → زبان: همان رفتار.
۴. `Esc` → فهرست؛ `Esc` دوم → برگشت به بازی.
