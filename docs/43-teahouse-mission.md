# ۴۳ — مأموریت «شاهد آخر»: صحنه‌ی چای‌خانه

## ۱. تصمیم

این مأموریت یک **صحنه‌ی جدا** است، نه گوشه‌ای از `Sandbox`:

| تصمیم | چرا |
| --- | --- |
| صحنه‌ی مستقل `Scenes/Teahouse.unity` | مأموریت یک شب است، در جای دیگری؛ باز کردن صحنه و زدن `Play` باید کافی باشد |
| دیالوگ با همان تگ‌های موجود | اگر تگ تازه لازم شود، یعنی طراحی هنوز آماده نیست. پارسر روی تگ ناشناخته خطا می‌دهد |
| ساخت صحنه با `tools/make_teahouse_scene.py` | فایل صحنه YAML است؛ ساخت دستی تکرارپذیر نیست. اسکریپت از `Sandbox` شروع می‌کند و فقط دفتر را برمی‌دارد |
| مأموریت در `Resources/Quests/witness.txt` | کارها داده‌اند، نه کد؛ تب کارها خودش می‌خواند |

صحنه از `Sandbox` این‌ها را نگه می‌دارد و دست نمی‌زند: بازیکن، دوربین و ریگ
Cinemachine، `HUD`، منوی توقف، `EventSystem`، `DialogueSystem` و `World`.

## ۲. مکان و آدم‌ها

اتاق ۱۰×۸ متر، دیوارهای ۱٫۲ متری (همان زبان بصری دفتر)، بدون سقف، دوربین از بالا.

```text
        درِ آشپزخانه (به پس‌کوچه)
   ┌──────────────┬────┐
   │              │    │
   │  میز ۱   میز ۲    │  پیشخوان
   │  ○  ○     ○  ○    │  ▬▬▬▬  مسعود
   │                  │  (قبض روی پیشخوان)
   │                  │
   └───────  درِ ورودی ─┘
              بازیکن
```

| آبجکت | نقش |
| --- | --- |
| `Masoud` | `TalkInteractable` + `DialogueStarter` → `masoud_teahouse.txt` |
| `Chit` | `DocumentInteractable` → `Documents/teahouse_chit`، با خواندن `flag.clue.chit` |
| `Spike` / `Spike_Base` | سیخی که قبض‌ها به آن می‌روند؛ دلیل بودنِ قبض روی پیشخوان |
| `Counter`, `Cupboard`, `Samovar` | پیشخوان و پشت پیشخوان |
| `Table_1`, `Table_2`, `Stool_1..4` | میزهای مشتری |
| `KitchenDoor` | درِ بسته‌ی آشپزخانه؛ همان دری که شریفی از آن بیرون رفت |
| `Light_Counter`, `Light_Table`, `Light_Door` | سه نور گرم نقطه‌ای |

ساعت صحنه روی **۱۳۵۲/۰۵/۱۳، ساعت ۲۱:۱۰** است. یعنی شب سیزدهم مرداد، چند
ساعت پیش از آن‌که مسعود صبح جسد را پیدا کند. `SunDriver` خودش ماه را بالا می‌آورد.

## ۳. پرچم‌ها

| پرچم | مقدار | نوشته‌شده توسط |
| --- | --- | --- |
| `flag.quest.witness` | 0 نشده · 1 در جریان · 2 تمام | دیالوگ |
| `flag.witness.talked` | true = یک بار حرف زده‌ای | دیالوگ |
| `flag.clue.chit` | true = قبض را خوانده‌ای | `DocumentInteractable` |
| `flag.witness.truth` | true = حقیقت را گرفته‌ای | دیالوگ |
| `flag.witness.deal` | true = با بلیت کویت خریده‌ای | دیالوگ |
| `flag.witness.threat` | true = تهدیدش کرده‌ای | دیالوگ |
| `flag.witness.protect` | true = قول حمایت داده‌ای | دیالوگ |
| `known.witness.name` | true = اسم یزدانی را داری | فقط مسیر «بلیت» |
| `known.masoud.threat` | true = می‌داند تهدیدش کردی | فقط مسیر «تهدید» |

سه پرچم آخر عمداً از هم جدا هستند: **چیزی که گفتی** با **چیزی که او باور کرد**
یکی نیست. مسیر تهدید اسم را نمی‌دهد؛ مسیر حمایت نصف حقیقت را می‌دهد و یک قرار.

## ۴. جریان

```text
start ── سه انتخاب کوچک (شب / پول / چای) ──> brush ──> end
  │
  │ (قبض خوانده شده)
  ▼
chit ──┬─ بلیت کویت ──> deal     → truth + اسم یزدانی + پرونده‌ی کامل
       ├─ تهدید      ──> threat   → truth بدون اسم + آبرو پایین
       ├─ اداره      ──> protect  → truth نصفه + قرار فردا شب + آبرو بالا
       └─ فعلاً هیچی  ──> leave
```

سه گره‌ی پایانی (`after_deal`, `after_threat`, `after_protect`) وقتی صدا زده
می‌شوند که `flag.witness.truth` روشن باشد؛ هر کدام یک خط کوتاه دارد، نه یک
توضیح دوباره.

**نکته‌ی ترتیب:** `[do] flag.quest.witness = 1` در گره `chit` هم هست، چون
بازیکن می‌تواند قبض را **قبل از اولین گفت‌وگو** بخواند. اگر نبود، کار هرگز
باز نمی‌شد.

## ۵. چرا این دیالوگ «پرکننده» نیست

قاعده‌هایی که موقع نوشتن رعایت شد:

1. **هر جمله یک کار می‌کند:** یا اطلاعات می‌دهد، یا فشار می‌آورد، یا سکوت است.
   جمله‌ی تزئینی («چه شب زیبایی») هیچ‌جا نیست.
2. **مسعود چانه می‌زند.** اول انکار، بعد اشاره، بعد قیمت. حقیقت یک‌جا نمی‌آید.
3. **عددها مشخص‌اند.** یازده و بیست، یازده و چهل‌وپنج، شش صبح، دویست تومن.
   این‌ها همان چیزهایی هستند که یک شاهد واقعی یادش می‌ماند.
4. **دروغِ رسمی یک کلمه است: «ده».** همان «ما ساعت ده می‌بندیم» که گروهبان
   گفته بنویسد، و همان که مسعود دو بار تکرارش می‌کند. پرونده هم روی همین
   یک کلمه بنا شده.
5. **حقیقت در هر مسیر یکسان نیست.** پول اسم می‌خرد، تهدید فقط جسد را، حمایت
   فقط «تنها نبود» را. بازیکن باید بفهمد چه چیزی نخریده.
6. **هیچ‌کس توضیح نمی‌دهد.** سرنخ‌ها در جزئیات‌اند: یک قهوه‌ی ترک در قبض یعنی
   نفر دومی بوده؛ «حسابش را من دادم» یعنی مسعود ضرر کرده و انگیزه دارد.

## ۶. پیامدها

### آبرو — دو قاعده‌ی تازه

| شناسه | شرط | شرافت | صداقت | وفاداری |
| --- | --- | --- | --- | --- |
| `witness_protect` | `flag.witness.protect` | +۸ | ۰ | +۴ |
| `witness_threat` | `flag.witness.threat` | −۸ | −۵ | ۰ |

مسیر «بلیت» عمداً هیچ قاعده‌ای ندارد: خریدن راه خروج نه فضیلت است نه گناه،
یک معامله است. بازی درباره‌اش قضاوت نمی‌کند.

### کار

`Resources/Quests/witness.txt` — کار «شاهد آخر» با دو قدم:

| قدم | متن | شرط |
| --- | --- | --- |
| `slip` | قبض‌های شب سیزدهم را بگرد | `flag.clue.chit != true` |
| `talk` | مسعود را به حرف بکشان | `true` |

کار با `flag.quest.witness == 1` باز می‌شود، نه از اول: در دفتر و بایگانی
هنوز کسی به این چای‌خانه نرفته و نباید در فهرست کارها بیاید. برای همین `==`
نوشته شده، نه `>=` — متغیر نانوشته با `==` نادرست است.

### کاغذها

`Documents/teahouse_chit` با خواندن، خودکار در `flag.seen.teahouse_chit`
ثبت می‌شود (`DocumentLog`)، پس در تب «پرونده‌ها»ی منوی توقف دیده می‌شود.
هیچ صحنه‌ای لازم نیست یادش باشد چیزی را علامت بزند.

## ۸. آزمایش

1. صحنه‌ی `Assets/_Project/Scenes/Teahouse.unity` را باز کن و `Play` بزن.
2. `WASD` تا پیشخوان. `E` روی قبض → برگه باز می‌شود. `Esc` ببند.
3. `E` روی مسعود → سه انتخاب کوچک. هر سه به یک «برو، مشتری می‌آد» می‌رسند.
4. دوباره سراغ قبض برو، بخوانش، بعد با مسعود حرف بزن. حالا چهار انتخاب جدی داری.

| مسیر | انتظار در تب کاراکتر |
| --- | --- |
| تهدید | شرافت ۴۲، صداقت ۴۵، وفاداری ۵۰ — در کنسول `[Reputation] witness_threat` |
| اداره | شرافت ۵۸، وفاداری ۵۴ — `[Reputation] witness_protect` |
| بلیت | هر سه ۵۰ — عددی عوض نمی‌شود، ولی `known.witness.name` روشن است |
| فعلاً هیچی | عددی عوض نمی‌شود؛ کار باز می‌ماند |

5. `Esc` → تب کاراکتر: کار «شاهد آخر» با قدم جاری؛ تب پرونده‌ها: قبض.
6. بعد از گرفتن حقیقت، دوباره با مسعود حرف بزن → گره‌ی پایانی همان مسیر.

**تست بیرون از یونیتی:** `dialoguecheck` هر ۸ فایل و ۱۰۹ گره را بی‌ایراد
می‌بیند؛ `scenecheck` صحنه‌ی ساخته‌شده را با ۵۹۷ ارجاع، صفر مشکل. مسیرهای
دیالوگ با یک شبیه‌ساز کوچک دور زده شدند: ۳ مسیر اولین گفت‌وگو، ۴ مسیر با
قبض، و ۳ گره‌ی پایانی — هیچ مسیری بدون `[end]` تمام نمی‌شود.

## ۹. محدودیت‌ها

- **این صحنه در Unity باز و Play نشده.** ساخت با اسکریپت و بررسی با
  `scenecheck` است؛ اگر Unity خطایی داد، همان خطا باید اول درست شود.
- **درِ آشپزخانه انیمیشن ندارد.** قرار «فردا شب، ساعت نه» یک قلاب برای
  مأموریت بعدی است، نه یک وعده‌ی اجراشده.
- **صداپیشگی ندارد.** جمله‌های داخل پرانتز («سرش را بلند نمی‌کند.») متن‌اند،
  نه حرکت؛ تنها راه بیانِ بدن در نوار دیالوگ.
- **خروجی اسکریپت، صحنه را بازنویسی می‌کند.** اگر صحنه را دستی در Unity
  عوض کردی، دیگر `make_teahouse_scene.py` را اجرا نکن، یا تغییرها را اول
  داخل اسکریپت ببر.
