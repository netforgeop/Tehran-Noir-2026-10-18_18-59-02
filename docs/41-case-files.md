# ۴۱. کارها و پرونده‌ها — دو بخشِ تازه در تب کاراکتر

تاریخ: ۲۰۲۶-۱۱-۱۲ — جلسه‌ی ۴۰

## ۱. تصمیم

در تب «کاراکتر» منوی توقف، دو بخشِ آخر تا امروز پیام «این بخش در مرحله‌ی بعد
ساخته می‌شود» را نشان می‌دادند. حالا هر دو داده و تصویر دارند:

| بخش | چه چیزی نشان می‌دهد | منبع |
| --- | --- | --- |
| کارها | کارهای باز، نوعشان، و قدمی که همین حالا باید انجام شود | `QuestLog` |
| پرونده‌ها | کاغذهایی که باز کرده‌ای، با عنوان و تاریخ؛ کلیک = بازخوانی | `DocumentLog` |

تصمیم قبلی (`docs/29`) دست‌نخورده مانده: پرونده‌ها تب جدا نشد و همان‌جای خودش
در تب کاراکتر ماند. دلیلش همان است که آن روز نوشته شد: چهار تب بالای صفحه
بیشتر از این شلوغ می‌شود، و این دو بخش به هم تعلق دارند — کار می‌گوید چه کاری
بکن، پرونده‌ها می‌گویند چه مدرکی داری.

## ۲. یک کلاس برای دو بخش

`Scripts/UI/Pause/DossierSection.cs` یک کلاس است که با یک حالت ساخته می‌شود:

```text
DossierSection(Menu, Mode.Jobs)
DossierSection(Menu, Mode.Documents)
```

چیدمان، ردیف، ناوبری و ماوسشان یکی است؛ فقط داده و کارِ Enter فرق می‌کند.
اگر دو کلاس می‌شد، هر اصلاح چیدمان باید دو بار انجام می‌شد و دو رفتار از هم
جدا می‌افتاد — همان چیزی که در بخش وسایل با `CharacterItemsSection` حل شد.

## ۳. از کاغذ تا فهرست

نشانه‌گذاری در **یک** جا انجام می‌شود: `DocumentView.Show`. هر سندی که روی
صفحه بیاید — از تعامل روی میز، از منوی ادیتور، از پنل تست — یک کلید می‌گذارد:

```text
flag.seen.<نام فایل> = true
```

پس فهرست، دفتر جداگانه‌ای ندارد که با واقعیت جدا بیفتد. چرخه این است:

```text
DocumentLayer.ShowResource  →  DocumentView.Show  →  DocumentLog.Note
                                                          ↓
                                      WorldState: flag.seen.file_sealed = true
                                                          ↓
                     DossierSection(Documents) ← DocumentCatalog + DocumentLog.Seen
```

| فایل | نقش |
| --- | --- |
| `Documents/DocumentLog.cs` | نوشتن و خواندن نشانه؛ `KeyOf` مسیر و پسوند را پاک می‌کند |
| `Documents/DocumentCatalog.cs` | همه‌ی فایل‌های `Resources/Documents` را یک بار می‌خواند و کش می‌کند |
| `UI/Pause/DossierSection.cs` | فهرست، ردیف‌ها، انتخاب، بازخوانی |
| `UI/Pause/CharacterPauseTab.cs` | بخش ۲ و ۳ را به همین کلاس می‌سپارد |
| `UI/PauseMenuUI.cs` | تا سند باز است ورودی منو را نمی‌خواند |

**چرا `flag.` و نه پیشوند تازه؟** پیشوند تازه یعنی دست‌زدن به
`WorldState.IsKnownVariable`، به پارسر شرط و به ابزار گیت، بدون هیچ سود واقعی.

## ۴. چیدمان (۱۹۲۰×۱۰۸۰، مبدأ بالا؛ داخل ستون محتوا)

| عنصر | اندازه |
| --- | --- |
| سرخط بخش | y=۰، فونت ۲۶، طلایی، بولد |
| شمار | گوشه‌ی مقابل سرخط، فونت ۲۲، خاکستری |
| خط زیر سرخط | y=۴۸، ضخامت ۱ |
| ردیف | از y=۶۴، ارتفاع ۷۰، فاصله ۶، حداکثر ۷ ردیف |
| نام | فونت ۲۴؛ زیرش خط توضیح با فونت ۱۷ |
| نشان نوع | عرض ۱۵۰، ارتفاع ۲۸، لبه‌ی ۴ |

ردیف انتخاب‌شده پس‌زمینه‌ی گرم‌تر و نام طلایی می‌گیرد، مثل بقیه‌ی منو.
نشان نوع در فارسی سمت چپ ردیف می‌نشیند و در انگلیسی سمت راست.

## ۵. ناوبری

| کلید | کار |
| --- | --- |
| `Q` / `E` | تعویض بخش (خلاصه / وسایل / کارها / پرونده‌ها) |
| `W` / `S` یا فلش‌ها | حرکت بین ردیف‌ها |
| `Enter` یا کلیک | در پرونده‌ها: بازخوانی سند انتخاب‌شده |
| `Esc` | اول به خلاصه، دوم بستن منو |

نوار پایین صفحه هم دیگر دروغ نمی‌گوید: در تب‌هایی که بخش دارند، کنار بج
`Q`/`E` نوشته می‌شود «تعویض بخش»، نه «تعویض تب» (`pause.section`).

## ۶. بازخوانی سند از داخل منو

سند روی لایه‌ی اسناد بالاتر از منو ساخته می‌شود (مرتبه ۳۰۰ برابر ۱۰۰)، پس
متن روی منو می‌آید. دو نکته‌ی مهم:

۱. تا سند باز است، `PauseMenuUI` هیچ ورودی‌ای نمی‌خواند
   (`DocumentView.Busy`). بدون این، یک `Esc` هم سند را می‌بست هم منو را —
   همان فریمی که سند `_open` را `false` می‌کند، منو هم همان کلید را می‌دید.
۲. `Busy` تا پایان محوِ بسته‌شدن `true` می‌ماند، نه فقط تا لحظه‌ی `Close`؛
   وگرنه همان یک فریم کافی بود.

راهنمای پایین صفحه، وقتی ردیف سند انتخاب است، می‌گوید «برای بازخوانی، کلید
تایید را بزن»؛ وقتی ردیف کار است، خلاصه‌ی همان کار را نشان می‌دهد.

## ۷. زبان و ارقام

- عنوان و تاریخ و شماره از خود سند خوانده می‌شوند و با `DocumentText.Pick`
  به زبان جاری درمی‌آیند.
- سندی که `[title]` ندارد (یادداشت دست‌نویس) اولین خط غیرخالی‌اش را نشان
  می‌دهد، کوتاه‌شده با سه‌نقطه؛ نه نام فایل.
- شمار ردیف‌ها **ASCII** به TMP داده می‌شود و `ForceFix` می‌خورد؛ قاعده‌ی
  همیشگی: رقم فارسی را خودمان نمی‌سازیم.

## ۸. محدودیت‌های این مرحله

| مورد | وضعیت |
| --- | --- |
| بیش از ۷ ردیف | سه‌نقطه نشان داده می‌شود؛ صفحه‌بندی نیست |
| تخته‌ی سرنخ (پین کردن مدرک) | نیست؛ مرحله‌ی بعدِ همین بخش |
| جست‌وجو یا فیلتر | نیست |
| ذخیره‌ی `flag.seen.*` در فایل | نیست؛ با آمدن سیستم ذخیره خودکار می‌آید |
| بازخوانی از داخل منو | هست، ولی سند روی منو باز می‌شود، نه داخل خودِ تب |

## ۹. آزمایش

| گام | انتظار |
| --- | --- |
| بازی را اجرا کن و هنوز چیزی نخوانده، منو را باز کن | بخش «پرونده‌ها»: «هنوز سندی نخوانده‌ای.» |
| پرونده‌ی روی میز را باز کن، بعد منو | در فهرست، عنوان پرونده با تاریخ و شماره |
| `Enter` روی همان ردیف | خود پرونده دوباره باز می‌شود؛ `Esc` سند را می‌بندد و منو باز می‌ماند |
| بخش «کارها» | کار «پرونده‌ی محرمانه» با قدم فعلی و نشان «اصلی» |
| کار را با `F10` پیش ببر | خط زیر نام، بدون بستن منو عوض می‌شود |
| `Q` / `E` | بخش‌ها می‌چرخند و راهنمای پایین «تعویض بخش» می‌گوید |
| زبان انگلیسی | ردیف‌ها چپ‌چین، عنوان‌ها لاتین، ارقام همان عددهای سند |
