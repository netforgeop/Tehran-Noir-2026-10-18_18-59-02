# ۴۰. دفتر ثبت بایگانی: سند، نه دیالوگ

تاریخ: ۲۰۲۶-۱۱-۱۲ — جلسه‌ی سی‌وششم

## ۱. مسئله

دفتر ثبت بایگانی با `SimpleInteractable` و `DialogueStarter` ساخته شده بود.
یعنی وقتی بازیکن «می‌خواندش»، متنش در **نوار دیالوگ پایین صفحه** می‌آمد.

دو ایراد:

| ایراد | چرا بد بود |
| --- | --- |
| دفتر مثل دیالوگ پخش می‌شد | دفتر یک سند است؛ باید یک برگه‌ی جدول‌دار وسط صفحه باز شود |
| متن ثابت بود | از اول می‌گفت «مهر سالم تحویل داده شد»، حتی وقتی پرونده‌ی بازیکن مهر شکسته داشت |

ایراد دوم بدتر است: دیالوگ ثابت، به واقعیت بازی نگاه نمی‌کند. هر بار پرونده
جابه‌جا می‌شد، دفتر همان جمله‌ی قبلی را می‌گفت.

## ۲. اصلاح یک: قالب «دفتر»

`DocumentTemplate` حالا سه حالت دارد: `Letter`، `Note`، `Ledger`.

| قالب | شکل |
| --- | --- |
| `Letter` | نشان، سرصفحه، شماره و تاریخ، متن، مهر |
| `Note` | تکه‌کاغذ کج، فقط متن |
| `Ledger` | سرصفحه‌ی چاپی + سرستون‌ها + ردیف‌های جدول + پانویس |

در `Ledger` هر خانه جدا کشیده می‌شود، نه یک متن بلند. چرا؟ اگر همه‌ی ردیف یک
متن باشد، ستون‌ها با تغییر فونت به‌هم می‌ریزند؛ با یک متن برای هر خانه، ستون‌ها
دقیقاً زیر هم می‌ایستند.

## ۳. اصلاح دو: ردیف شرط‌دار

سند حالا همان فکر `[if]` دیالوگ را دارد، برای کاغذ:

```text
[when] شرط
[row] ...
[always]
```

`[when]` ردیف‌ها و خط‌های بعدی را تا `[always]` یا تا `[when]` بعدی نگهبان می‌کند.
شرط با همان `ConditionParser` دیالوگ سنجیده می‌شود؛ پس `flag.*`، `item.*`،
`rel.*` و `state.*` همه کار می‌کنند.

ردیف بازیکن در `archive_log.txt`:

```text
[when] (flag.quest.file == 3 or flag.quest.file == 4) and flag.file.opened != true
[row] ...؛ نادر راد | Nader Rad؛ مهر سالم | seal intact
```

و برای مهر شکسته، چهار ردیف جدا بر اساس آنچه بازیکن گفته:

| شرط | نوشته‌ی ستون وضعیت |
| --- | --- |
| `flag.claim.seal == opened` | مهر شکسته — با اقرار |
| `flag.claim.seal == already` | مهر شکسته — ادعای باز شدن قبلی |
| `flag.claim.seal == none` | مهر شکسته — منکر |
| `flag.claim.seal == unknown` | مهر شکسته — نامعلوم |

یعنی دفتر همان چیزی را می‌نویسد که نادر گفته، نه لزوماً واقعیت. این همان
«سه دفتر باور» است، روی کاغذ.

### تله‌ای که وسط کار پیدا شد

اول شرط را `flag.quest.file >= 3` نوشتم. با متغیر تعریف‌نشده، موتور شرط عدد
ندارد، پس مقایسه **متنی** می‌شود:

| شرط | با متغیر تعریف‌نشده | نتیجه |
| --- | --- | --- |
| `flag.quest.file >= 3` | `"flag.quest.file"` با `"3"` مقایسه می‌شود؛ حرف `f` از رقم `3` بزرگ‌تر است | **درست** |
| `flag.quest.file == 3` | دو رشته‌ی نابرابر | نادرست |

یعنی همان `>=` باعث می‌شد ردیف نادر از اول دیده شود — دقیقاً همان ایرادی که
باید رفع می‌شد. پس در شرط‌هایی که «هنوز هیچ‌چیز ثبت نشده» باید نادرست باشند،
همیشه `==` نوشته می‌شود. این در سرصفحه‌ی خود فایل سند هم توضیح داده شده.

## ۴. دست‌نویس

`[hand] true` ردیف‌ها را دست‌نویس می‌کند:

| ابزار | کار |
| --- | --- |
| رنگ جوهر | آبی-مشکی، نه سیاه چاپی |
| لرزش | هر خانه بین ۰٫۷۵- تا ۰٫۷۵+ درجه، پایدار برای هر ردیف |
| پخش جوهر | یک نسخه‌ی کم‌رنگ، نیم‌پیکسل جابه‌جا، پیش از متن اصلی |
| فونت | اگر فیلد `Handwriting Font` پر باشد، همان؛ وگرنه فونت معمولی |

لرزش برای هر خانه از یک عدد ثابت می‌آید (`Jitter(seed)`)، پس سند هر فریم
نمی‌لرزد و با هر بار باز شدن یک شکل است.

سرستون‌ها چاپی و ریز می‌مانند، ردیف‌ها دست‌نویس. این همان چیزی است که در
دفترهای اداری آن دوره دیده می‌شود: فرم چاپی، پر شده با خودکار.

**فونت دست‌نویس واقعی:** یک TTF دست‌نویس فارسی بگیر (مثلاً از
`rastikerdar` یا هر فونت آزاد دیگر)، در Unity یک `Font Asset` از آن بساز
(Dynamic)، و در کامپوننت `Document View` فیلد `Handwriting Font` را پر کن.
بدون آن هم حس دست‌نویس هست، ولی با فونت واقعی کامل می‌شود.

## ۵. دفتر، جعبه‌ی ۱۳۵۲ را باز می‌کند

`DocumentInteractable` فیلد `On Read Variable` دارد. روی دفتر ست شده:

```text
flag.clue.log
```

یعنی خواندن دفتر همان کاری را می‌کند که قبلاً دیالوگ می‌کرد: جعبه‌ی ۱۳۵۲ از
قفسه بیرون می‌آید. این‌بار بدون هیچ خط دیالوگ.

## ۶. تنظیم در صحنه

یک منوی تازه، فقط برای دفتر موجود:

```text
Tehran Noir → اتصال دفتر ثبت به سند
```

این منو روی آبجکت `Logbook` این کارها را می‌کند:

۱. `DialogueStarter` را برمی‌دارد (منبع پخش در نوار پایین).
۲. `SimpleInteractable` را برمی‌دارد.
۳. `DocumentInteractable` اضافه می‌کند.
۴. مسیر سند را `Documents/archive_log` می‌گذارد.
۵. متغیر خواندن را `flag.clue.log` می‌گذارد.
۶. صحنه را ذخیره می‌کند.

چرا منوی جدا و نه ساخت دوباره؟ منوی «ساخت بایگانی و مأموریت» کل `ArchiveWing`
را پاک و از نو می‌سازد. این منو فقط دفتر را عوض می‌کند و بقیه‌ی صحنه
دست‌نخورده می‌ماند.

## ۷. تست

کامپوننت تازه: `DocumentSelfTest`. روی یک آبجکت خالی بگذار و Play بزن.
انتظار: **۱۹ قبول، ۰ رد** (سه بررسیِ دفتر دیده‌ها در جلسه‌ی ۴۰ اضافه شد — `docs/41`).

| تست | چه چیزی را ثابت می‌کند |
| --- | --- |
| سند بار شد | فایل در `Resources/Documents` هست |
| قالب دفتر است | `[template] ledger` درست خوانده شد |
| ستون‌ها پارس شدند | پنج ستون |
| ردیف‌ها پارس شدند | نه ردیف در فایل |
| هر ردیف پنج خانه دارد | خانه‌ها با `؛` درست جدا شدند |
| بدون تحویل، ردیف بازیکن نیست | دنیای تازه: چهار ردیف قدیمی، هیچ «نادر» |
| دست رضا: هنوز ردیف بازیکن نیست | `flag.quest.file = 2` ردیف اضافه نمی‌کند |
| تحویل سالم: ردیف آمد | پنج ردیف، وضعیت «مهر سالم» |
| مهر شکسته با اقرار | وضعیت «با اقرار» |
| مهر شکسته با انکار | وضعیت «منکر» |
| شرط بدخط، ردیف را پنهان می‌کند | سند نمی‌شکند و ردیف دیده نمی‌شود |
| یادداشت بار شد | فایل `Documents/note_yazdani` وجود دارد |
| یادداشت قالب note دارد | `[template] note` درست خوانده شد |
| یادداشت سه خط دارد | سه خط متن، بدون حساب خط‌های خالی |
| یادداشت دست‌نویس است | `[hand] true` خوانده شد |

## ۸. گیت تازه برای سندها

`tools/storycheck.py` حالا `Resources/Documents/*.txt` را هم می‌خواند:

| بررسی | خطای بی‌صدا که می‌گیرد |
| --- | --- |
| `item.<id>` در `[when]` | شناسه‌ی غلط → خط یا ردیف هرگز دیده نمی‌شود |
| تعداد خانه‌های `[row]` با `[columns]` | جدول جابه‌جا چاپ می‌شود |
| ردیف بدون `[columns]` | ستون‌ها معلوم نیستند |

با یک ردیف شش‌خانه‌ای و یک شناسه‌ی غلط، خروجی شد `problems: 2` و کد خروج ۱.

## ۹. یادداشت هم سند است، نه دیالوگ

بعد از دفتر، یادداشت هنوز با `SimpleInteractable` و `DialogueStarter` ساخته می‌شد؛
یعنی خواندنش متن را در نوار پایین می‌آورد. همان ایراد، یک کاغذ دیگر.

| کاغذ | قبلاً | حالا |
| --- | --- | --- |
| دفتر ثبت | دیالوگ با جمله‌ی ثابت | سند `Documents/archive_log` |
| یادداشت | دیالوگ با سه خط ثابت | سند `Documents/note_yazdani` |

سازنده‌ی صحنه حالا یک تابع مشترک دارد و هر کاغذ تازه یک خط است:

```text
Paper(parent, "Note", position, size, material,
      "یادداشت|Note", "دست‌نویس|Handwritten",
      NoteDocument, "flag.clue.note");
```

`DocumentInteractable` همان کاری را می‌کند که دیالوگ می‌کرد، ولی روی کاغذ:
با خواندن، `flag.clue.note` روشن می‌شود. پس مسیر رضا (`[if] flag.clue.note == true -> note`)
همان‌طور کار می‌کند.

### منوی تبدیل برای صحنه‌ی موجود

```text
Tehran Noir → اتصال یادداشت به سند
```

این منو روی آبجکت `Note` این کارها را می‌کند: `DialogueStarter` و `SimpleInteractable`
را برمی‌دارد، `DocumentInteractable` می‌گذارد، مسیر سند و متغیر خواندن را ست
می‌کند و صحنه را ذخیره می‌کند. منوی دفتر هم به همان بدنه‌ی مشترک وصل شد.

فایل `Dialogue/note_yazdani.txt` دیگر خوانده نمی‌شود. اگر خواستی، خودت پاکش کن؛
حذفش اجباری نیست ولی دو منبع برای یک واقعیت، همان تلّه‌ی همیشگی است.

### دست‌نویس برای یادداشت

`[hand] true` در یادداشت هم گذاشته شد. تا این نسخه، دست‌نویس فقط روی ردیف‌های
جدول اثر داشت؛ حالا بدنه‌ی هر سندی که `[hand] true` داشته باشد هم با جوهر
آبی-مشکی، فونت دست‌نویس (اگر ست شده باشد) و کمی کج نوشته می‌شود.

### شکستن خط در جدول

در عکس، خانه‌های بلند («صورت‌جلسه‌ی بازجویی دوم») روی ستون کناری می‌افتادند.
حالا هر خانه دو خط جا دارد: ارتفاع ردیف ۵۸، فونت ۱۵، شکستن خط روشن.
جدول با نه ردیف هم داخل برگه می‌ماند.
