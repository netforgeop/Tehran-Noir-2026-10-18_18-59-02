# زبان دیالوگ — مرجع کامل

راهنمای نوشتن فایل `.txt` دیالوگ. هر قاعده‌ای که اینجا نیست، در پارسر هم وجود ندارد.

## ۱) ساختار فایل

```text
[person] reza
[name] رضا | Reza
[role] صاحب مغازه | Shopkeeper
[cast] reza
[cast] nad

[node] greet
[say] reza | سلام. | Hello.
[go] ask
```

- هر خط با یک تگ `[...]` شروع می‌شود. خط خالی و خطی که با `#` شروع شود نادیده گرفته می‌شود.
- ترتیب مهم است: `[person]`/`[name]`/`[role]`/`[cast]` قبل از اولین `[node]`.
- شناسه‌ها به حروف کوچک تبدیل می‌شوند، پس `Reza` و `reza` یکی هستند.
- گوینده در `[say]` باید در `[cast]` باشد، وگرنه هشدار می‌گیری (خطا نیست).

## ۲) تگ‌ها

| تگ | شکل | کار |
| --- | --- | --- |
| `[person]` | `[person] id` | شناسه‌ی گوینده‌ی اصلی فایل |
| `[name]` | `[name] فارسی \| English` | نام، دو زبانه |
| `[role]` | `[role] فارسی \| English` | نقش، دو زبانه |
| `[cast]` | `[cast] id` | هر شخص حاضر در این دیالوگ (تکرارشدنی) |
| `[node]` | `[node] id` | شروع یک گره |
| `[say]` | `[say] گوینده \| فارسی \| English` | یک خط دیالوگ |
| `[opt]` | `[opt] فارسی \| English -> مقصد` | یک گزینه |
| `[go]` | `[go] مقصد` | پرش بدون انتخاب |
| `[if]` | `[if] شرط` | شرط چسبان برای خطوط بعدی |
| `[if]` | `[if] شرط -> مقصد` | پرش شرطی |
| `[else]` | `[else]` | پایان شرط چسبان |
| `[do]` | `[do] متغیر عملگر مقدار` | تغییر جهان |
| `[end]` | `[end]` | پایان دیالوگ |

## ۳) متغیرها

| متغیر | نوع | مقدار اولیه |
| --- | --- | --- |
| `time` | متن | `morning` (یا `noon` / `evening` / `night`) |
| `weather` | متن | `clear` (یا `rain` / `fog` / `snow`) |
| `energy` `fear` `sanity` `trust` `playerAge` | عدد | `energy=100`، `fear=0`، بقیه `0` |
| `rel.<id>` | عدد | `0` |
| `met.<id>` | بولی | `false` |
| `present.<id>` | بولی | `false` |
| `flag.<name>` | عدد | `0` |

متغیرهای `rel.` / `met.` / `present.` / `flag.` با هر نامی که بنویسی، خودکار ساخته می‌شوند.
نام‌ها **حساس به حروف بزرگ و کوچک** هستند: `met.Reza` با `met.reza` فرق دارد.

## ۴) شرط‌ها

عملگرها: `==` `!=` `>` `<` `>=` `<=` و `and` `or` `not` و پرانتز.

اولویت از بالا به پایین:

```
مقایسه  →  not  →  and  →  or
```

چند نمونه‌ی پیچیده:

```text
[if] met.reza == true and (rel.reza >= 40 or flag.bribe_paid == 1)
[if] not (time == morning) and weather == rain
[if] energy < 30 or fear > 60
[if] met.reza and present.nad and rel.nad < 20
```

قاعده‌ها:

- عدد با عدد → مقایسه‌ی عددی. متن با متن → مقایسه‌ی متنی.
- هر دو طرف اگر عددی باشند، عدد حساب می‌شوند؛ حتی اگر متن باشند (`"12"`).
- `time == night` و `time == "night"` هر دو کار می‌کنند. سمت راست بدون گیومه، اگر متغیری با آن نام نباشد، با نام خودش مقایسه می‌شود.
- متغیر تعریف‌نشده: در شرط `false` است، در مقایسه با نام خودش سنجیده می‌شود.
- `not` را با پرانتز بگذار: `not (a and b)`.
- **حساب نیست**: `energy - 10 > 20` و `-5` و `a > b > c` خطا می‌دهند. فقط یک عملگر مقایسه در هر شرط.

## ۵) شرط چسبان `[if] cond` — مهم‌ترین قاعده

`[if]` بدون `->` روی **همه‌ی خطوط بعدی** اثر می‌گذارد، تا:

- `[if]` بعدی برسد → شرط **جایگزین** می‌شود (جمع نمی‌شود)،
- یا `[else]` برسد → شرط **پاک** می‌شود.

```text
[node] ask
[if] fear > 50
[say] reza | دستات می‌لرزه.
[if] met.reza == false
[say] reza | تو غریبه‌ای.
[else]
[say] reza | بازم تو.
[go] next
```

- خط «دستات می‌لرزه» فقط با `fear > 50` می‌آید.
- خط «تو غریبه‌ای» فقط با `met.reza == false` می‌آید (شرط قبلی جایگزین شده).
- خط «بازم تو» با هر وضعیتی می‌آید، چون `[else]` شرط را پاک کرد.

برای برگشتن به حالت بی‌شرط، یک `[else]` تنها بگذار.

## ۶) پرش شرطی `[if] cond -> target`

- شرط **خودش** سنجیده می‌شود، و اگر داخل یک شرط چسبان باشد، شرط چسبان هم لازم است.
- ترتیب بررسی، ترتیب نوشتن است: اولین پرشی که شرطش برقرار باشد اجرا می‌شود.
- پرش شرطی، شرط چسبان را تغییر **نمی‌دهد**.

```text
[node] greet_known
[if] rel.reza >= 50 -> greet_friend
[if] rel.reza >= 20 -> greet_acquaintance
[go] greet_stranger
```

## ۷) `[do]`

| شکل | کار |
| --- | --- |
| `[do] rel.reza +5` | ۵ اضافه |
| `[do] fear -10` | ۱۰ کم |
| `[do] met.reza = true` | بولی |
| `[do] time = night` | متن |
| `[do] flag.bribe_paid = 1` | عدد |

`[do]` هم شرط چسبان را رعایت می‌کند.

## ۸) گزینه‌ها

- شماره‌گذاری خودکار است؛ عدد را ننویس.
- **گزینه‌های یک بلوک باید پشت سر هم باشند.** اولین خط غیرِ `[opt]` بلوک را می‌بندد.
- بین دو گزینه `[if]` یا `[else]` نگذار؛ بلوک را می‌شکند.

بد (گزینه‌ی دوم هیچ‌وقت دیده نمی‌شود):

```text
[opt] A -> x
[if] fear > 50
[opt] B -> y
```

درست (دو بلوک کامل):

```text
[if] fear > 50
[opt] A -> x
[opt] B -> y
[else]
[opt] C -> z
[opt] D -> w
```

با `fear > 50` گزینه‌های A و B می‌آیند؛ وگرنه C و D.

- کلیدهای `1` تا `9` کار می‌کنند؛ بیش از ۴ گزینه در پنل جا نمی‌شود.

## ۹) یک گره‌ی کامل و پیچیده

```text
[node] ask_night
[say] reza | دیشب اینجا بودی؟ | Were you here last night?
[if] flag.saw_body == 1 and not met.nad
[say] reza | صورتت رنگ پریده. چی دیدی؟ | You look pale. What did you see?
[do] fear +10
[if] trust > 30 or rel.reza >= 40
[opt] راستش را می‌گویم | I will tell you the truth -> confess
[opt] هیچی، خواب بد دیدم | Nothing, just a bad dream -> lie
[else]
[opt] چیز مهمی نبود | It was nothing -> lie
```

## ۱۰) خطاها و هشدارها

| پیام | معنی |
| --- | --- |
| `هر خط باید با یک تگ شروع شود` | خط بدون `[...]` |
| `تگ ناشناخته` | تگ در فهرست نیست |
| `مقصد پیدا نشد` | پرش به گره‌ی ناموجود |
| `node ... بن‌بست` | گره نه `[opt]` دارد نه `[go]` نه `[end]` |
| `شناسه تکراری` | دو `[node]` با یک نام |
| `شرط نامعتبر: ...` | خطای نحوی در شرط |
| `فقط مسیرهای شرطی دارد` (هشدار) | اگر هیچ شرطی برقرار نشود، دیالوگ تمام می‌شود |

خطا یعنی دیالوگ اجرا نمی‌شود؛ هشدار یعنی اجرا می‌شود ولی احتمالاً منطق اشتباه است.

## ۱۱) تست در Unity

در `DialogueTestTrigger`:

- `Keep World Between Dialogues` روشن باشد تا `met.reza` بعد از اولین صحبت ثبت بماند.
- `Initial Variables` برای ساختن وضعیت اولیه، مثلاً:
  - `met.reza = true`
  - `rel.reza = 45`
  - `time = night`
  - `flag.saw_body = 1`
- برای پاک کردن جهان: راست‌کلیک روی کامپوننت → **ریست جهان**.

## ۱۲) چک‌لیست قبل از تست

1. هر گره حداقل یک راه خروج دارد: `[opt]` یا `[go]` یا `[end]`.
2. هر مقصد، یک `[node]` موجود است.
3. هر `[if]` چسبان قبل از خطی است که باید مشروط باشد.
4. `[else]` بعد از بلوک مشروط گذاشته شده.
5. گزینه‌های هر بلوک پشت سر هم‌اند.
6. `[cast]` همه‌ی گویندگان را دارد.
